## 2. 已确认的业务规则（原型依据）

- 名称统一为 **Full愈年卡**，不使用“大会员 / VIP会员”。
- **365 元 / 365 天**；权益期从支付成功时刻起算。
- **提前一天及以上预约 78 折；当日预约 88 折**（按服务开始日期比较，不看下单时刻）。
- 开卡 / 续费时写入 **费率快照**；后台调价只影响之后新开或新续的权益期。
- 结算比价四选一：**年卡价 / 通用折扣 / 积分抵扣 / Full愈券**，互不叠加。
- **默认选现金最低**；同价按「年卡 → 通用折扣 → 积分 → 券」优先，避免无谓消耗积分和券。
- 用户可手动切换方案，切换只改应付金额与 `priceSource`，不改订单原价。
- 仅服务项目订单适用；商品、券包、礼品卡、储值卡充值、接待订单不适用。
- 续费未到期时从当前 `endTime` 顺延；已到期则等同新开。
- **强制退款仅后台可发起**，必须填写原因，默认全额、可改；退款后该权益期立即失效，已发生订单优惠不回溯。
- 储值卡（富翁卡）继续售卖与核销，个人中心降级到「我的权益」折叠区。
- 到期前 **30 天**在小程序与后台提示；主动推送放批次五。

### 已验证交互（浏览器实测）

- 首次加载：提前档，年卡价 ¥702，自动选中「年卡提前价」。
- 切到「当日」：年卡价同步为 ¥792，并重新自动取最低。
- 手动点「积分抵扣」：应付 ¥800，提示「已切换为「积分抵扣」，优惠方案之间不可叠加」。
- 点「Full愈券支付」（需 3 张、仅有 1 张）：置灰不可选，Toast「Full愈券不足，还差 2 张」，当前选中项不变。
- 切回「提前」：恢复 ¥702 / 年卡提前价。
- 协议勾选：勾选前 `disabled=true`，勾选后可点击；再次取消恢复置灰。
- 「确认支付」：Toast「已选择：积分抵扣，应付 ¥800」。
- 控制台：无报错。

## 4. 后台原型：页面与状态

文件：`Full愈-会员卡管理-PC端Demo.html`，1600 × 1050，Element UI 风格，主色 `#6750A4`，侧栏 `#304156`。

| 页面 | 内容 |
|---|---|

## 5. 实现落点（待批准后执行）

### 5.1 SQL

新增 `tou-mall-server/sql/2026-11-07-member-card.sql`：

1. `s_member_card_config`（配置，单行生效）
2. `c_customer_member_card`（权益期，每次开 / 续一条）
3. `c_member_card_order`（开卡支付单，独立于商品订单）
4. `s_order` 增加 `price_source`、`member_card_id`、`member_rate`、`benefit_amount`（均可空，历史订单不受影响）

### 5.2 后端（mall-admin 为主）

- 实体 / Mapper：`MemberCardConfig`、`CustomerMemberCard`、`MemberCardOrder`；沿用 MyBatis-Plus。
- `MemberCardService`：配置读写、开卡、续费、退款、分页、详情、到期扫描。
- `MemberCardPayService`：开卡支付单创建、支付回调幂等（按 `order_sn`）、退款调用现有汇付通道。
- `PriceComparisonService`：输入原价、服务日期、积分、可用券数；输出四方案、默认项、应付与优惠额。
- `OrderService` 接入：
  - `buildOrder` / `checkout` 计算 `priceOptions`；
  - `payCheckout` 按用户选择落 `price_source`、`pay_amount`、`benefit_amount`；
  - 券方案继续走现有 `COUPON` 支付类型。
- 后台 Controller：`/memberCard/page|detail|issue|renew|refund|config|expiring`，退款单独授权。
- 定时任务：每日 00:10 扫描到期 / 待生效；30 天提醒只打标，不推送。
- 权限：新增菜单「会员卡」挂「客户」分组；退款、配置单独资源点。

### 5.3 小程序（full-yu-mini2）

## 7. 需要确认的 4 个口径

1. **后台电话预约**是否同样享受年卡价？当前设计：允许（按服务日期判定）。
2. **退款金额**默认全额还是按未使用天数折算？当前设计：默认全额，可手工改。
3. 年卡是否包含**非价格权益**（赠品、专属客服等）？当前设计：仅折扣，权益表后续扩展。
4. 到期提醒是否需要**短信 / 公众号推送**？当前设计：本批只做站内提示，推送放批次五。

以上不阻塞实现，按当前默认即可开工；若有不同口径，改动集中在配置与服务层，不影响页面结构。
