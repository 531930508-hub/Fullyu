# 需求设计：疗愈师偏好标记「收藏 / 暂别」（客户级技师偏好）

> 状态：待用户复核设计稿后进入开发
> 日期：2026-09-30（2026-10-08 更名与交互统一改版）
> 交互 Demo：
> - 小程序端：`/Full愈轻疗-技师不再预约-小程序交互Demo.html`
> - 后台：`/Full愈后台-客户技师偏好-交互设计Demo.html`
>
> **命名说明**：对外统一口径为「收藏 / **暂别**」（原「不再预约」，2026-10-08 更名）。本文件名与两个 Demo 文件名保留旧字样，以免既有链接失效；正文中「屏蔽」为技术语义，不得出现在任何界面文案里。

---

## 1. 需求背景

客户对某位技师不合适（手劲、沟通、气场等原因）时，目前没有任何办法避免下次再被分配到该技师。需要支持：

1. 客户自己标记某技师「暂别」，未来该客户的预约（指定或自动分配）都不会匹配到该技师；
2. 门店后台可以**代客户**设置技师暂别与技师收藏；
3. 话术柔和，不叫「拉黑」；
4. **与既有「收藏」在同一交互层面**：收藏现在是一点即切换的心形图标（`favorite-therapist.png` ↔ `shoucangselect.png` + 「收藏/已收藏」文字，见 `order-detail.vue` L81-85、`collect.vue` L50），暂别必须做成同规格、同语法的配对控件，而不是另起一个文字入口 + 弹窗（见 2.1）。

## 2. 命名与话术（对外统一口径）

对外只有一对词：**收藏（♥）** 与 **暂别（🌙）**，合称「疗愈师偏好」。禁用词：拉黑、屏蔽、黑名单、不再预约（旧口径，已废弃）。

| 场景 | 对外话术 | 禁用词 |
|------|---------|--------|
| 功能名 | 疗愈师偏好：收藏 / 暂别 | 拉黑、屏蔽、黑名单、不再预约 |
| 控件文字（未点亮 / 点亮） | 「收藏」/「已收藏」 · 「暂别」/「已暂别」 | — |
| 确认弹窗标题 | 「暂时不约 TA？」 | 「不再预约TA？」 |
| 确认弹窗正文 | 之后预约时会自动避开「{技师名}」，TA 不会收到任何通知，随时可以恢复。 | — |
| 确认弹窗按钮 | 再想想 / 暂时不约 | — |
| 设为暂别 Toast | 已设为暂别，之后自动避开 TA | — |
| 解除入口 | 「解除暂别」（点已点亮的 🌙 即解除） | 取消拉黑、恢复预约 |
| 解除 Toast | 已恢复，可以正常预约 TA 了 | — |
| 收藏页分段筛选 | 全部 / 想再约 / 暂别 | — |
| 互斥轻提示 | 已同时取消对 TA 的收藏 / 已同时解除暂别 | — |
| 空状态 | 还没有暂别的疗愈师 | — |
| 技师端感知 | 完全无感知（不通知、不展示） | — |
| 后台（内部员工可见） | 与 C 端同词「暂别」，抽屉 tab-tip 补一句解释：暂别 = 该客户不想再被分配到这位疗愈师 | 黑名单 |

内部代码/表/接口命名仍用 `block`（`c_customer_massagist_block`、`CustomerMassagistBlock`、`/customerMassagistBlock`），仅对外文案柔化。

### 2.1 控件形态：偏好双标（解决「两个层面」问题）

收藏与暂别是同一维度的一对互斥状态，必须做成**同规格、同语法**的一对图标 toggle：

| 规格 | 收藏 | 暂别 |
|------|------|------|
| 图标 | 30rpx，现有 `favorite-therapist.png`（空心）↔ `shoucangselect.png`（实心） | 30rpx，**新增同风格线性图标 2 枚**：空心（带斜线的心 / 月形）↔ 点亮态 |
| 文字 | 26rpx「收藏 / 已收藏」 | 26rpx「暂别 / 已暂别」 |
| 颜色 | 未选 `#8A6A40`，点亮 `#C4A974` | 未选 `#8A6A40`（与收藏同族，保证成对感），点亮 **暖灰 `#7A736B`**——不用红色，避免惩罚感 |
| 位置 | 疗愈师行 / 卡片同一行，紧邻排列，暂别在收藏右侧 | 同 |
| 交互 | 点一下点亮，再点一下熄灭 | 完全相同 |
| 互斥表现 | 点亮一个 → 另一个自动熄灭 + 一行轻提示 | 同 |

不复用 `ban-solid-red.svg` / `circle-x.png`：视觉过于「禁止」，与柔和口径冲突。

> **色值约束**：点亮态必须比未选态**更深**，否则「点亮」失去可供性。`#7A736B`（暖灰，比 `#8A6A40` 更沉）满足这一点；`#B3AFA9` 只用于**辅助信息**（设置来源与时间、「已暂别」小标签、占位说明文字），不得用作图标点亮色。

### 2.2 打断时机统一原则

**「获得 / 恢复不打断，失去 / 生效才确认」**——两个标记共用同一条规则，而非各写一套：

| 动作 | 弹窗 | 现状/说明 |
|------|------|----------|
| 点亮 ♥ 收藏 | 否 | 现状保持（`toggleFavorite` 直接调接口） |
| 熄灭 ♥ 取消收藏 | 是 | 现状保持（`order-detail.vue` L303、`collect.vue` L150 / L262 的 `uni.showModal`） |
| 点亮 🌙 设为暂别 | **是** | 影响后续派单；弹窗正文是功能说明的主落点（见 2.3） |
| 熄灭 🌙 解除暂别 | 否 | 即时生效 + Toast「已恢复，可以正常预约 TA 了」 |

### 2.3 功能说明落点（「有个地方说明一下这个是干嘛的」）

| 落点 | 内容 | 版本 |
|------|------|------|
| 设为暂别的确认弹窗正文 | 完整解释：之后自动避开 / TA 不会收到通知 / 随时可恢复 | v1（**主落点**） |
| 收藏页「暂别」筛选态顶部说明条 | 一行：暂别的疗愈师不会出现在你的预约和自动分配里，随时可以解除 | v1 |
| 「暂别」筛选空状态 | 🌿 插画 +「还没有暂别的疗愈师」 | v1 |
| 后台偏好抽屉 tab-tip | 内部解释 + 建议对客话术（「帮您先避开这位疗愈师」） | v1 |
| 首次点亮 🌙 的一次性气泡引导 | 文案同说明条，只出现一次 | v1.1 可选 |

## 4. 业务规则

1. **互斥**：暂别与收藏互斥（技术上：屏蔽记录与收藏记录互斥）。设为暂别时自动取消已有收藏；点亮收藏时自动解除已有暂别。UI 表现为「点亮一个、另一个自动熄灭」，并给一行轻提示（`已同时取消对 TA 的收藏` / `已同时解除暂别`），不额外弹窗。
2. **作用域**：客户级（`customer_id + massagist_id` 唯一），跨门店生效——该技师在哪家门店都避开。
3. **C 端预约链路硬拦截**（服务端为准，前端仅体验优化）：
   - 自动分配：`OrderService.findAvailableMassagistList` / `findAvailableMassagistListNew` 排除该客户屏蔽的技师后再进入排序（`sortMassagist`）；
   - 指定技师：`createOrder`（`fullyMiniCreateOrder`）校验 `massagistIdList`，命中屏蔽则返回业务提示「该疗愈师暂不可预约，请选择其他疗愈师」；
   - 时段查询：`/order/timeList` 指定 `massagistId` 时同样校验；
   - 智能预约技师列表：数据源接口过滤已屏蔽技师。
4. **后台排班看板区别对待**（门店是受信操作者，服务不硬拦截）：
   - **手动指定**：命中屏蔽仅弹确认提示，员工确认后照常下单（服务端不校验不拦截）；
   - **自动派人**（建单时未指定技师 / 指定人数不足自动补位）：服务端跳过被屏蔽技师；
   - 详见第 8 章。
5. **可逆**：解除暂别 = 删除屏蔽记录，立即生效，**不需要二次确认**（见 2.2）；历史订单/评价不受影响。
6. **来源留痕**：屏蔽记录区分 `source`：1=客户本人（小程序）设置，2=门店后台代设；后台代设额外记录操作管理员账号。后台代客户收藏同样记录来源与操作人。
7. **技师无感知**：不通知技师，技师端任何列表/统计不体现被暂别。
8. **存量兼容**：不影响积分逻辑（`IntegrationService` 读收藏关系）——暂别记录使用独立新表，不动 `c_customer_massagist_relation`。
9. **交互一致性（本次改版的硬要求）**：暂别在 C 端出现的每一处，都必须与收藏以「同规格图标对」形态并列出现（2.1）、共用同一条打断规则（2.2）。禁止把暂别做成独立的文字链入口或独立 Tab。

## 5. 数据模型

新表 `c_customer_massagist_block`（收藏复用现有 `c_customer_massagist_relation`，不加列、不迁移）：

```sql
CREATE TABLE `c_customer_massagist_block` (
  `id`           BIGINT       NOT NULL AUTO_INCREMENT,
  `customer_id`  BIGINT       NOT NULL COMMENT '客户id c_customer.id',
  `massagist_id` BIGINT       NOT NULL COMMENT '疗愈师id s_massagist.id',
  `source`       TINYINT      NOT NULL DEFAULT 1 COMMENT '来源 1=客户本人 2=门店后台代设',
  `create_by`    VARCHAR(64)  DEFAULT NULL COMMENT '操作人：后台为管理员账号；客户本人为空',
  `create_time`  DATETIME     DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_customer_massagist` (`customer_id`,`massagist_id`)
) COMMENT='客户暂别的疗愈师（客户级偏好标记，对外话术见 §2）';
```

后台代客户收藏需要留痕时，为 `c_customer_massagist_relation` 增加可空列 `source`/`create_by`（不破坏现有逻辑）。

实体/Mapper/Service/Controller 放在 mall-admin（与 `CustomerMassagistRelation` 同级同模式）：
- `entity/CustomerMassagistBlock.java`（`@TableName("c_customer_massagist_block")`，transient `massagist`）
- `mapper/CustomerMassagistBlockMapper.java`
- `service/CustomerMassagistBlockService.java`（create 幂等去重 + 屏蔽时同步删收藏；pageInfo 关联 Massagist）
- `controller/CustomerMassagistBlockController.java`

## 6. 接口设计

### 6.1 小程序端（客户身份，`curCustomerId()`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/customerMassagistBlock/create/relation?massagistId=` | POST | 设为暂别（服务端同步删收藏关系，事务） |
| `/customerMassagistBlock/get/page` | GET | 我的暂别列表（nested massagist，同收藏 `/get/page` 模式） |
| `/customerMassagistBlock/get/ids` | GET | 我的暂别 massagistId 数组（轻量）：供预约页/智能预约前端过滤与兜底提示，**同时用于渲染卡片上 🌙 的点亮态** |
| `/customerMassagistBlock/{id}` | DELETE | 解除暂别 |

`api/customerMassagistBlock.js` 按 `api/customerMassagistRelation.js` 同样封装。

### 6.2 后台端（管理员身份）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/customerMassagistBlock/page?customerId=&page=&size=` | GET | 按客户分页查屏蔽（nested massagist） |
| `/customerMassagistBlock/byPhone?phone=` | GET | 按手机号轻量查该客户屏蔽的技师 id+姓名数组（排班看板建单抽屉用，客户不存在时返回空数组） |
| `/customerMassagistBlock` | POST | 代客户屏蔽，body：`{customerId, massagistId, source:2, createBy:当前管理员}` |
| `/customerMassagistBlock/{id}` | DELETE | 解除暂别（后台与小程序共用） |

后台代客户**收藏**：复用现有 `/customerMassagistRelation` 的 `POST`（body 带 customerId）与 `GET /page?customerId=`，无新增接口（如需留痕则加 source/create_by 列）。

### 6.3 预约链路改造点（关键代码位置）

| 位置 | 改动 |
|------|------|
| `OrderService.findAvailableMassagistList`（~L327） | 取 `curCustomerId` 屏蔽 id 列表，从候选中剔除 |
| `OrderService.findAvailableMassagistListNew`（~L3491） | 同上；另增可选 `phone` 参数：按手机号解析客户，给返回列表打 `blockedByCustomer` 瞬态标记（**不从列表剔除**，供排班看板提示用，见第 8 章） |
| `OrderService.fullyMiniCreateOrder`（~L2520） | 校验 `massagistIdList` 不含屏蔽 id，否则 `CommonResult.failed("该疗愈师暂不可预约，请选择其他疗愈师")` |
| `/order/timeList`（含 New/Edit 变体） | 指定 `massagistId` 命中屏蔽时该技师时段不返回/报提示 |
| `OrderDetailService.createDetail`（~L442-498）及 `createDetail0410`（~L2604-2640） | **自动补位/自动派人跳过屏蔽**：从 `sortedMassagistIdList`（自动池）与「从全部补足」的兜底列表中剔除该客户屏蔽的技师；员工**指定**的技师 id 原样通过，不做校验（覆盖小程序、`appointmentOrder`、接待单共用链路） |

| `/order/timeListlx`（`findArriveTimeList0410`） | 不改动：时段列表在客户识别前拉取，且手动指定仅提示不禁止，硬隐藏时段会与之矛盾；不足场景由下单时自动跳过后的报错兜底 |

> 注意：PC 排班看板（首页建单）的**手动指定**不受客户屏蔽硬限制，仅弹确认提示；**自动派人**跳过屏蔽。详见第 8 章。

## 8. 首页排班看板补充设计（后台建单场景）

> 原则：门店是受信操作者——**手动指定仅提示、绝不拦截；自动派人一律跳过**。与 C 端「看不见 + 硬拦截」形成对比。

### 8.1 建单时指定了客户已「暂别」的技师 → 仅提示不强制禁止

现状链路：看板空格子点击（`index.vue showAppointment`）→ `AppointmentDrawer.open(form, params)`（`params.name` 会按点击的技师列/床位预选）→ 员工在「疗愈师」checkbox 组（`massagistListNew` 返回）勾选 → `appointmentOrder` 下单。客户靠手机号 autocomplete 识别，`appointmentOrder` 服务端按 phone 查/建客户。

实现方案（前端提示 + 列表打标，服务端零拦截）：

1. **列表打标**：`GET /order/massagistListNew`（含接待用的 `massagistListNewLx`）增加可选参数 `phone`；`findAvailableMassagistListNew` 内按 phone 解析客户（查不到则无屏蔽），给返回的 `Massagist` 打瞬态标记 `blockedByCustomer=true`。**被屏蔽技师保留在列表中**（员工要能看到、能指定，才能「提示后照常下单」）。
2. **前端重拉时机**：`AppointmentDrawer` 在客户被识别时（`handleSelectCustomer` / phone watcher 命中已知客户）带 `phone` 重拉技师列表刷新标记——覆盖「先勾技师、后输手机号」的操作顺序。
3. **视觉标记**：被暂别的 checkbox 按钮加橙色虚线边框 + 「暂别」小角标，hover 提示「该客户已把这位疗愈师设为暂别（不想再被分配到 TA）」。
4. **勾选拦截改为确认**：勾到被标记技师时先回退勾选，弹 `$confirm`：

   > 标题：仍要为该客户指定「李敏」吗？
   > 正文：李敏 是该客户设为「暂别」的疗愈师。如客户在现场同意，可继续指定；此设置仅对本次订单生效，不会改变客户的偏好记录。
   > 按钮：不指定 / 仍要指定

   确认后正常勾选。若当前已勾选中含被标记技师且客户中途变更，同样确认一次。
5. **提交前可见提醒**：存在已勾选的被标记技师时，表单底部出现一条 `el-alert warning`：「本次安排包含客户设为暂别的疗愈师：李敏，请与客户确认」。
6. **服务端不拦截**：`appointmentOrder` / `createDetail` 对员工指定的 `massagistIdList` 原样通过。这是与 C 端的唯一原则差异：员工有机会当场与客户确认，系统不替门店做决定。

加钟（同抽屉 `drawerTitle="加钟"`）与 `UpdOrderForm` 修改订单走同一列表与同一确认逻辑。

### 8.2 看板上展示客户的暂别名单

### 8.3 看板建单的自动派人跳过逻辑

现状链路：`appointmentOrder`（`OrderService` L2544）按 phone 解析出 `customerId` 后组装 `OrderDetailDto` → `buildOrder` → `orderDetailService.createDetail(dto, isManage, true)`。`createDetail` 内：

- 勾选人数不足时从 `sortedMassagistIdList`（= `sortMassagist(availableMassagistIdList, …)`，L443/L456）自动补位（L450-461）；
- 完全未指定时直接取排序结果（L462-472）；
- 最后还有「从全部排班技师兜底补足」（L489-498）。

改动（一处覆盖所有入口：小程序、PC 建单、接待单）：

1. 在 `createDetail` 与 `createDetail0410` 中，拿 `orderDetailDto.getCustomerId()` 查屏蔽 id 列表（一次性 `select massagist_id from c_customer_massagist_block where customer_id=?`，可加本地缓存）；
2. **仅从自动来源中剔除**：
   - `sortedMassagistIdList`（自动池，L443 之后过滤）；
   - 指定不足时的补位循环（L450-461 / 2604 对应处）；
   - 「从全部补足」兜底（L491-498 / 2640 对应处）；
3. **不动的**：员工指定的 `massgistIdList`、`availableMassagistList.size() < personCount` 的容量校验（L423）——保证「提示后照常下单」在服务端成立；
4. **兜底不足时**：剔除后自动池不足人数 → 维持现有报错路径（「疗愈师不满足人数要求」），小程序端由「自动切换门店安排 + 提示」承接（见小程序 Demo 场景③），PC 端员工看到报错后可手动指定（走 8.1 的提示确认）作为安全阀；
5. 接待单（`createReceptionDetail`，type=接待）为纯接待性质，v1 不做跳过；列表接口的标记照常返回，无副作用。

`/order/timeListlx` 时段列表**不改**：时段在客户识别前拉取、且手动指定仅提示——若按时段隐藏会把「提示不禁止」变成「变相禁止」，与 8.1 矛盾。

## 9. 边界与空状态

- 收藏页分段筛选默认停在「想再约」，与今天的收藏列表行为完全一致（老用户无感知）
- 「暂别」筛选态：顶部一行说明条 + 空状态 🌿 插画 +「还没有暂别的疗愈师」
- 暂别数量不设上限；列表按设置时间倒序
- 技师离职（status=0）后仍保留暂别记录，列表置灰显示「已离职」
- 客户注销/删除客户时同步清理其暂别记录（随现有客户清理逻辑）
- 重复设为暂别幂等（唯一键兜底，返回成功）

## 10. 验收要点

1. 客户 A 暂别技师 T 后：自动分配永不含 T；指定 T 下单被拦且有柔和提示；timeList 不出现 T。
2. 暂别后收藏自动取消；再收藏 T 时暂别自动解除；两种互斥都有轻提示、都不额外弹窗。
3. 后台可为客户添加/移除暂别与收藏，来源与操作人正确显示。
4. 小程序各处入口文案与 §2 话术表、Demo 一致，全程无「拉黑 / 屏蔽 / 黑名单 / 不再预约」字样。
5. 技师端无任何「被暂别」感知（技师端列表/统计不体现）。
6. **控件一致性**：♥ 与 🌙 在订单详情页、收藏页卡片两处均为同尺寸图标（30rpx）+ 同字号文字（26rpx）并列；点亮/熄灭手感一致；🌙 未选 `#8A6A40`、点亮 `#7A736B`（暖灰而非红色），`#B3AFA9` 仅用于辅助信息。
7. **打断规则**：点亮收藏、解除暂别不弹窗；取消收藏、设为暂别弹窗（弹窗正文含「自动避开 / 不通知 TA / 随时可恢复」三要素）。
8. **收藏页**：Tab 仍为「疗愈师 / 门店」两个；疗愈师 Tab 内分段筛选默认「想再约」，切到「暂别」出现说明条与对应列表，在暂别态点 ♥ 可直接转为收藏。
9. **看板建单**：手机号识别客户后，抽屉内出现该客户暂别标签；勾选被暂别技师弹确认、确认后可正常下单成功（服务端不报错）；未勾选自动派人时结果不含被暂别技师；自动池不足时报错文案正确。
10. **订单详情**：客户信息区正确显示技师偏好只读行。
