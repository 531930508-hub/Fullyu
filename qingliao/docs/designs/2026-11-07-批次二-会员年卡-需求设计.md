# 批次二：Full愈年卡（会员卡）需求设计

> 状态：原型待确认，未改生产代码
> 范围：小程序会员中心 + 结算比价 + 后台会员卡管理
> 前置批次：批次一（暂别、接待工时封顶、激励合并）已完成源码改造

---

## 0. 一句话结论

做一张 **365 元 / 365 天**的 Full愈年卡：**提前一天及以上预约 78 折，当日预约 88 折**；开卡时把费率快照写进卡记录，后续调价不影响已购卡；结算时把「年卡价 / 通用折扣 / 积分 / Full愈券」放在一起比价，**默认选现金最低的一种，可手动切换，四种优惠不叠加**；后台支持手工开卡、强制退款、调价配置和到期提醒；现有储值卡（富翁卡）继续可用，但在小程序里降级收纳。

---

## 1. 业务边界与用词

| 项 | 结论 |
|---|---|
| 对外名称 | Full愈年卡（不叫“大会员”“VIP会员”） |
| 价格 | 365 元 / 年（后台可改） |
| 权益期 | 365 天，按开通时刻起算 |
| 折扣 | 提前预约 78 折；当日预约 88 折（后台可改，默认 0.78 / 0.88） |
| 适用对象 | 服务项目订单（PMS 服务）；不含商品零售、券包、礼品卡、储值卡充值、接待订单 |
| 叠加规则 | 年卡价、通用折扣、积分抵扣、Full愈券四种方案 **互斥，不叠加** |
| 默认方案 | 四种方案中 **现金支付最低** 的一种，同价时按「年卡 → 通用折扣 → 积分 → 券」顺序 |
| 费率快照 | 开卡 / 续费时写入当期费率；改配置只影响之后新开或新续的权益期 |
| 储值卡 | 继续售卖与核销，个人中心与商城入口降级、折叠，不与年卡并列 |
| 续费提醒 | 到期前 30 天在小程序与后台提示；主动推送放批次五 |

**统一话术**

- 购买：「开通 Full愈年卡」
- 续费：「续费 Full愈年卡」
- 到期：「年卡已到期，续费后继续享受会员价」
- 退款：后台「强制退款」，对客不出现“强制”二字

## 2. 核心规则

### 2.1 折扣判定

以 **服务开始日期** 与 **今天** 比较，不看下单时刻：

```
serviceDate = 订单明细 startTime 的日期
isAdvance  = serviceDate > today          // 提前一天及以上
memberRate = isAdvance ? card.advanceRate : card.sameDayRate
```

- 今天约今天 → 88 折
- 今天约明天及以后 → 78 折
- 会员卡到期当天仍可用，次日 0 点起失效（按 endTime 精确到时分秒）

### 2.2 有效期与续费

- 新开：`startTime = 支付成功时刻`，`endTime = startTime + 365 天`
- 续费（未到期）：新权益期 `startTime = 当前卡 endTime`，`endTime = startTime + 365 天`
- 续费（已到期）：`startTime = 支付成功时刻`，等同新开
- 每开 / 续一次生成 **一条权益期记录**，同一客户可同时存在「当前生效」和「待生效」两条
- 待生效权益期不参与折扣判定，但后台可见、可退款
- 续费时采用 **续费当下** 的配置费率，不与上一期费率混用

### 2.3 比价引擎

输入：订单原价 `base`（按 30 分钟计价单位计算后的金额）、服务日期、客户积分、可用券次数、本次所需券次数。

候选方案：

| 方案 | 现金应付 | 附加消耗 | 可选项条件 |
|---|---|---|---|
| 年卡提前价 | `round(base × advanceRate, 2)` | 无 | 卡生效 且 提前预约 |
| 年卡当日价 | `round(base × sameDayRate, 2)` | 无 | 卡生效 且 当日预约 |
| 通用折扣 | 沿用 `OrderDiscountService` 结果 | 无 | 命中通用 / 新客折扣 |
| 积分抵扣 | `max(base - points, 0)` | 消耗 `min(points, ceil(base))` 积分 | 积分 > 0 |
| Full愈券 | `0` | 消耗 `ceil(总分钟 / 30)` 张券 | 可用券数足够 |

规则：

1. 现金最低者默认选中；同价按「年卡 → 通用折扣 → 积分 → 券」优先，避免无谓消耗积分和券。
2. 用户可手动切换；切换只改 `price_source` 与应付金额，不改变订单原价。
3. 券方案被选中时，订单支付方式记为 `COUPON`，现金为 0；其余方案走微信 / 汇付。
4. 积分方案不足全额时，剩余金额走微信；积分不与其他方案叠加。
5. 服务订单创建时先落原价；**最终方案在结算页确定并回写订单**，避免下单时锁死优惠。
6. 订单记录 `priceSource`、`memberCardId`、`memberRate`、`benefitAmount`，便于对账与客诉追溯。

### 2.4 计算示例

以 90 分钟服务、原价 900 元为例：

| 场景 | 应付 | 优惠 |
|---|---|---|
| 年卡提前价 | 900 × 0.78 = 702.00 | 198.00 |
| 年卡当日价 | 900 × 0.88 = 792.00 | 108.00 |
| 通用 9 折 | 810.00 | 90.00 |
| 1200 积分 | 0（消耗 900 积分，剩余 300） | 900.00 |
| 3 张 Full愈券 | 0（消耗 3 张） | 900.00 |

默认选中现金最低；若积分与券都能做到 0 元，按优先级选积分（券留作下次）。

### 2.5 退款

- 仅后台可发起，入口在会员卡详情；需要填写原因，可改退款金额（默认全额）。
- 退款成功后：该权益期立即置为「已退款」，折扣即时失效；已发生的订单优惠不回溯。
- 待生效的续费期可单独退款，不影响当前生效期。
- 退款调用现有汇付退款通道；若原支付渠道不可退，后台保留「线下已退」标记，避免重复退款。

  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

### 5.1 个人中心

现有结构：头像卡 → 权益条（富翁卡）→ 积分 / Full愈券 → 功能列表。

## 6. 后台 UI

### 6.1 会员卡列表

路由：`/customer/member-card`，菜单「会员卡」，位于「客户列表」分组。

### 6.4 配置页

- 展示「当前生效卡数 / 本月新开 / 本月退款」三个小指标

## 7. 状态机

权益期：

```
待生效(0) --开始时间到--> 生效(1) --到期任务--> 已过期(2)
     |                        |
     +------强制退款----------+--> 已退款(3)
```

- 到期任务每日 00:10 扫描 `status=1 AND end_time < now` → 2；`status=0 AND start_time <= now AND end_time > now` → 1。
- 退款优先于到期：已退款不再转过期。

开卡支付单：

```
待支付(0) --支付成功--> 已支付(1) --退款--> 已退款(3)
待支付(0) --超时/关闭--> 已关闭(2)
```

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| 下单后改期跨日 | 结算时按最新服务日期重算；已支付订单不自动补差，需取消重下 |
| 会员卡在结算过程中到期 | 结算接口实时校验；失效则剔除年卡方案并提示 |
| 同时有当前期与待生效期 | 折扣只用当前期；列表展示两条 |
| 重复支付回调 | 以 `order_sn` 幂等，已支付直接返回卡信息 |
| 退款后再次开卡 | 允许；生成新权益期，历史退款记录保留 |
| 手工开卡金额为 0 | 允许赠送；支付单金额 0、状态已支付，记录操作人 |
| 通用折扣与年卡同价 | 默认年卡（同价优先年卡），保证会员感知 |
| 积分刚好覆盖原价 | 应付 0，仍生成支付单并走完成支付流程 |
| 券数量足够但用户选现金 | 允许，券保留；默认仍选最低 |
| 服务项目原价为 0 | 所有方案均为 0，直接完成，不展示比价 |
| 跨门店 / 跨项目 | 年卡权益不区分门店与项目，按服务订单原价计算 |

## 9. 存量影响

1. **万元户/富翁卡**：继续售卖，个人中心从主权益位降级为「我的权益」折叠项；商城入口保留但排序后移。
2. **现有通用折扣**：逻辑不变，只作为比价候选之一；新客折扣仍按首单判定。
