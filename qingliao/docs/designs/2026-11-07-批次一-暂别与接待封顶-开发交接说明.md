## 1. 统一话术与边界

| 场景 | 用语 |
|---|---|
| 客户不想再约某位疗愈师 | 暂别 / 已暂别 / 解除暂别 |
| 恢复 | 已恢复，可以正常预约 TA 了 |
| 设置确认 | 暂时不约 TA？ |
| 确认弹层说明 | 之后预约时会自动避开「{name}」，TA 不会收到任何通知，随时可以恢复。 |
| 设置成功 | 已设为暂别，之后自动避开 TA |
| 收藏页分段 | 全部 / 想再约 / 暂别 |
| 暂别空状态 | 还没有暂别的疗愈师 |

- 禁止出现「黑名单 / 拉黑 / 屏蔽」等字样，包括后台内部界面。
- 数据库与技术字段仍使用 `block`（如 `c_customer_massagist_block`），仅技术语义，不出现在界面。
- 暂别与收藏互斥：设置暂别会删除同一位疗愈师的收藏；设置收藏会删除同一位疗愈师的暂别。
- 客户本人操作不发通知给疗愈师；后台代设会记录操作人。

## 3. 接待工时封顶 · 规则

### 3.1 计算口径

对「月份 × 疗愈师 × 门店」：

```
上限分钟 = 该疗愈师当月在该门店的排班在岗分钟 × 门店比例（默认 20%）
计入工时 = 按接待开始时间排序，逐单计入，累计不超过上限的分钟
超出分钟 = 接待总分钟 - 计入分钟
```

- 在岗时长**按排班算**，不引入打卡。
- 调店排班计入目标门店（`target_shop_id > 0` 时取目标门店，否则取所属门店）。
- 门店比例按门店单独配置；新开业门店可临时调整，稳定后改回 20%。
- 超出部分系数按 0 计：不计工时、不计薪；服务工时不受影响。
- 上限按门店分别计算，再做当月合计。
- 若疗愈师当月完全无排班记录：不封顶，避免历史/缺数据月份工资被清零。
- 若仅某门店当月无排班（如调店未补排班）：该门店接待不封顶，其余门店照常封顶。
- 薪资档位系数使用封顶后的 `totalWorkingHours`，因此封顶会同步影响阶梯档位，这是预期行为。

### 3.4 生效方式

封顶在**重新计算薪资**时生效，不会自动改写已生成的历史记录：

- 全局重算：`GET /salaryRecord/resetRecordNew`（当前实现只重算「上个月」）。
- 单技师重算：`GET /salaryRecord/reset?massagistId=&monthCode=`（从指定月份起重算）。
- 后台薪资明细页已有触发入口，按钮文案为「临时用请勿点击」，发布前建议改成更明确的运营文案。

统计页 `服务时长` 为实时查询，改配置后刷新即可看到封顶结果，不依赖薪资重算。月度看板顶部「疗愈师总时长」与薪资同源，同样实时反映封顶。

## 7. 开放口径（需业务确认）

1. **多门店封顶展示**：`receptionCapMinutes` 为各门店上限之和；若某门店因无排班未封顶，该店上限不计入合计。界面提示为「上限 N 分钟」，属近似汇总，不逐店展开。
2. **历史月份**：仅重算后的月份应用封顶；未重算月份保持原值。是否统一重算历史月需业务确认。
3. **调店漏排班**：当前按门店兜底不封顶；若业务要求「无排班即不计接待」，需改为该店按 0 封顶，并先补齐调店排班流程。
4. **接待单跨零点/跨月**：沿用现有 `endTime` 归月口径，未单独处理跨月拆分。
