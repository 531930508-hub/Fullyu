# Full愈轻疗 · AI Coding 设计与开发标准手册

> **用途**：供开发团队的 AI Coding 工具（GPT / Claude / 其他）作为系统提示词 / 上下文参考，确保所有 AI 产出的 UI/UX 设计和代码与 Full愈 品牌和现有系统保持一致。
>
> **维护规则**：本文档是快照，品牌权威源为 `/brand/BRAND.md`，配色权威源为 `packages/design-tokens/src/colors.ts`，冲突时以权威源为准。

## 一、品牌核心

| 维度 | 内容 |
|------|------|
| **品牌名** | Full愈（FULL YU） |
| **Slogan** | 放松有道 自在生活 |
| **名称寓意** | Full = 全感（五感沉浸的「Full域」）、中间点 = 生活暂停键、愈 = 疗愈 |
| **定位** | 上海都市中高端身心放松生活方式品牌 |
| **核心概念词** | 科学放松、五感六觉、Full域、身心在场、向内生长 |

### 2.3 官网/品牌全线

| Token | 色值 | 用途 |
|-------|------|------|
| **Deep Brown（主色）** | `#6B463C` / `--wood-700` | 按钮、链接、序号 |
| **Warm Cream（底色）** | `#F5E8D8` / `--sand-100` | 页面背景 |
| **Ink（暖棕文字）** | `--ink-900 #2B211A` / `--ink-700 #4A3C32` / `--ink-500 #655547` | 替代纯黑 |

**硬规则**：
1. 深色区块（`.bg-wood`）内按钮必须反色（`color: var(--sand-100)`）
2. 渐变底上禁止半透明字色（实测仅 1.62–2.23:1 对比度）
3. 调色后必须用浏览器 computed style 实测对比度，不得凭肉眼判断

## 四、组件规范

### 4.1 小程序组件

| 组件 | 规范 |
|------|------|
| **卡片** | 白底、圆角 32rpx、轻阴影或 1px 边框 |
| **主按钮** | 深棕底 `#584219` + 白字、圆角 44rpx、高度 88rpx |
| **次按钮** | 白底 + 棕色 1px 边框、棕色文字 |
| **底部弹窗（Sheet）** | 白底、顶部圆角 24px、右上 × 关闭、暗色遮罩 |
| **居中弹窗（Dialog）** | 卡片式、暗色遮罩、× 关闭 |
| **Toast** | 深灰底 + ✓ 图标、居顶展示、1.5s 自动消失 |
| **图标** | 细线条描边风格、棕色系、统一 stroke-width |
| **空状态** | 插画 + 一行说明文字 + 操作按钮 |

### 4.2 PC 后台组件

| 组件 | 规范 |
|------|------|
| **弹窗/抽屉** | Element UI 的 `el-dialog` / `el-drawer`，保持默认圆角 |
| **表格** | `el-table`，表头灰底、行高适中 |
| **按钮** | 主按钮用 `type="primary"`（自动应用 `#6750A4`），圆角按钮用 `round` |
| **表单** | `el-form` + `el-form-item`，label 右对齐 |
| **悬浮组件** | `position: fixed`，右下角，带阴影，可收起为圆形角标按钮 |

## 七、技术栈速查

### 小程序前端（full-yu-mini2）

| 项目 | 技术 |
|------|------|
| 框架 | Vue 3 + uni-app |
| 样式 | SCSS（`uni.scss` 设计令牌） + Tailwind CSS |
| HTTP | luch-request（`utils/fetch.js` 封装） |
| 状态 | 组件 data + uni.getStorageSync 缓存 |
| API 层 | `api/*.js`，按领域分文件 |
| 微信 SDK | 支付 / 分享 / 定位 / 头像昵称获取 |

**编码规范**：
- 样式以 Tailwind 原子类为主，仅在复杂交互时写 SCSS
- 颜色/间距/圆角使用 `$uni-*` 变量，禁止硬编码色值
- 新增 token 需同步更新 `uni.scss`
- API 文件按后端域划分，直接 import 使用

### PC 管理后台（tou-mall-admin-web）

| 项目 | 技术 |
|------|------|
| 框架 | Vue 2 + Vue CLI + Webpack |
| UI 库 | Element UI |
| 状态 | Vuex |
| 图表 | ECharts |
| 拖拽 | vuedraggable |
| 路由 | vue-router（动态路由注入） |

**编码规范**：
- 覆盖 Element UI 样式集中在 `src/styles/element-ui.scss`
- 主题变量在 `src/styles/variables.scss`
- 页面组件 scoped 样式，公共类名放全局文件
- API 层 `src/api/*` 按后端域划分

### 后端（tou-mall-server）

| 项目 | 技术 |
|------|------|
| 框架 | Spring Boot 2.7.5 |
| ORM | MyBatis Plus |
| 数据库 | MySQL |
| 认证 | JWT |
| 存储 | 阿里云 OSS |
| 支付 | 微信支付 + 汇付天下 |

## 九、AI Coding 工作流最佳实践

### 9.1 开始任务前必做

1. **加载上下文**：把本文档作为系统提示词或首轮上下文喂给 AI
2. **读取 UI 参考**：项目目录下 `UI/` 文件夹包含所有 Figma 导出的设计稿截图，要求 AI 先读取相关页面的设计图再动手
3. **理解现有代码**：让 AI 先读对应模块的路由、页面组件和 API 文件

### 9.2 设计阶段

1. **结构化流程**：了解现状 → 澄清需求（逐个确认，不要一步到位） → 对比 2–3 种方案 → 确认后再实现
2. **输出可交互原型**：要求 AI 输出可交互的 HTML Demo 而不是静态描述
3. **遵循设计系统**：所有新页面必须使用本文档定义的色彩、字体、组件和交互模式

### 9.3 编码阶段

1. **使用设计令牌**：小程序用 `$uni-*` 变量和 Tailwind；后台用 `variables.scss` 中的变量
2. **遵循现有模式**：新页面参照同类型已有页面的目录结构和代码风格
3. **API 分层**：新接口在对应 `api/*.js` 文件中添加，不在组件内直接写请求
4. **组件复用**：优先使用已有组件（后台的 ShopSelector、AppointmentDrawer 等）

### 9.4 验证阶段

1. **对比设计稿**：完成后截图与 `UI/` 文件夹中的设计图对比
2. **色值校验**：检查是否使用了本文档定义的色值，禁止自创色系
3. **交互一致性**：确认弹窗、Toast、空状态等交互方式与已有页面一致
