## 1. 功能概述

在 Full愈后台首页（排班看板页）增加**门店级待办事项**功能，支持文本录入当日待办、悬浮窗常驻展示、人工确认完成、完整操作审计轨迹。

**核心定位**：门店内所有员工共享的轻量任务看板，解决交接班口头传达易遗漏的问题。

---

## 2. 业务规则

### 2.1 作用域
- 待办按**门店**隔离，同门店所有员工共享同一份待办列表
- 切换门店选择器时，待办列表跟随切换

### 2.2 权限
- 本门店所有登录员工均可**新增**和**完成**待办
- 每条待办记录创建人与完成人，支持事后追溯

### 2.3 待办生命周期
- **新增**：录入文本内容，系统自动记录创建人 + 创建时间
- **完成**：人工点击勾选 → 弹窗二次确认 → 系统记录完成人 + 完成时间
- **逾期顺延**：当日未完成的待办自动顺延至次日，标记红色「昨日未完成」标签；持续未完成则持续顺延并保持逾期标记
- 每条待办独立，可单条完成，互不影响

### 2.4 数据保留
- 已完成待办在「已完成」Tab 中保留当日记录
- 历史记录通过右侧抽屉查看，按日期分组，支持状态筛选和时间范围筛选

## 3. UI 组件结构

### 3.1 悬浮卡片（Todo Card）
- **位置**：页面右下角固定定位（`right: 30px; bottom: 26px`）
- **尺寸**：宽 390px，最大高度约 460px（含头部 + 列表 + 底栏）
- **层级**：`z-index: 20`，始终浮于排班看板之上；确认弹窗遮罩 `z-index: 30`，历史抽屉 `z-index: 40`，Toast `z-index: 60`
- **可折叠**：点击最小化按钮收起为小徽章按钮，再点展开

#### 3.1.1 卡片头部
- 标题「门店待办」+ 右侧操作按钮组（新增 `＋`、最小化 `—`）
- 双 Tab 切换：「待完成」/「已完成」，各自显示计数徽章

#### 3.1.2 待完成列表
- 每条待办项：圆形勾选按钮 + 文本内容 + 元信息行
- 元信息：创建人 + 创建时间；逾期项额外显示红色逾期标签
- 列表区域可滚动，最大高度 340px

#### 3.1.3 已完成列表
- 每条完成项：绿色对勾图标 + 文本内容（灰色） + 时间轴
- 时间轴（左侧竖线样式）：
  - 第一行：**创建** 创建人 · 创建时间
  - 第二行：**完成** 完成人 · 完成时间

#### 3.1.4 底栏
- 待完成 Tab 下：左侧提示文字 + 右侧「＋ 新增待办」按钮
- 已完成 Tab 下：右侧变为「查看全部记录 →」链接按钮，点击打开历史抽屉

### 3.2 完成确认弹窗（Confirm Dialog）
- 居中模态弹窗，半透明遮罩层
- 标题「确认完成待办？」
- 说明文字 + 紫底区块回显待办内容
- 双按钮：取消 / 确认完成
- 确认后：Toast 提示「已记录完成时间」

### 3.3 历史记录抽屉（History Drawer）
- 从右侧滑出，宽 520px，半透明遮罩
- 标题「待办记录」+ 关闭按钮
- 筛选栏：状态筛选（全部 / 已完成 / 未完成）+ 时间范围（近7天 / 近30天 / 自定义）
- 记录按日期分组，每条记录显示：文本内容 + 创建人时间 + 完成人时间（双列布局）

## 5. 交互流程

### 5.1 新增待办
```
点击「＋ 新增待办」→ 弹出输入弹窗 → 输入文本 → 确认
→ 列表实时新增一条待办（顶部插入）
→ 同门店其他在线终端实时同步
```

### 5.2 完成待办
```
点击圆形勾选按钮 → 弹出确认弹窗（回显待办内容）→ 点击「确认完成」
→ 待办从「待完成」移入「已完成」Tab
→ 自动切换到「已完成」Tab
→ Toast 提示「已记录完成时间」
→ 待完成计数 -1，已完成计数 +1
```

### 5.3 查看历史
```
切换到「已完成」Tab → 底栏出现「查看全部记录 →」
→ 点击打开右侧历史抽屉
→ 可按状态/时间筛选
→ 记录按日期分组展示
```

### 5.4 折叠/展开
```
点击最小化按钮「—」→ 卡片收起为右下角圆形徽章（显示待办数）
→ 点击徽章 → 卡片重新展开
```

## 6. 数据模型建议

### 6.1 待办表 `shop_todo`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 主键 |
| shop_id | bigint | 所属门店 |
| content | varchar(500) | 待办内容 |
| status | tinyint | 0=待完成, 1=已完成 |
| original_date | date | 原始创建日期 |
| current_date | date | 当前归属日期（逾期顺延后会变） |
| create_by | bigint | 创建人 ID |
| create_by_name | varchar(50) | 创建人姓名（冗余，避免频繁 join） |
| create_time | datetime | 创建时间 |
| complete_by | bigint | 完成人 ID |
| complete_by_name | varchar(50) | 完成人姓名 |
| complete_time | datetime | 完成时间 |
| is_overdue | tinyint | 是否逾期（0/1） |

### 6.2 接口设计

| 接口 | 方法 | 说明 |
|------|------|------|
| `/admin/shopTodo/list` | GET | 获取指定门店当日待办列表（含逾期顺延项） |
| `/admin/shopTodo/create` | POST | 新增待办 |
| `/admin/shopTodo/complete/{id}` | PUT | 确认完成待办 |
| `/admin/shopTodo/history` | GET | 分页查询历史记录，支持状态/日期范围筛选 |

### 6.3 定时任务
- 每日 00:05 执行逾期顺延：将前一天 status=0 的待办 `current_date` 更新为当天，`is_overdue` 设为 1

## 7. 前端实现要点

### 7.1 组件拆分
在 `views/home/` 下新增：
- `TodoCard.vue` — 悬浮卡片主组件
- `TodoConfirmDialog.vue` — 完成确认弹窗
- `TodoHistoryDrawer.vue` — 历史记录抽屉

### 7.2 集成位置
- 在 `views/home/index.vue` 的 template 末尾引入 `<TodoCard />`
- TodoCard 通过 `props` 接收当前选中的 `shopId`，内部自行管理数据请求

### 7.3 实时同步
- 方案一（推荐）：30 秒轮询，复用首页已有的定时器机制
- 方案二：WebSocket 推送（如后续有更多实时需求再升级）

### 7.4 响应式
- 屏幕宽度 ≤ 900px 时：侧边栏隐藏，卡片宽度收窄至 370px，历史抽屉宽度改为 92%

## 8. 边界情况

- 当日无待办时，列表区显示空状态插画 + 「暂无待办，点击右上角 ＋ 新增」
- 待办文本不超过 500 字，超出截断并提示
- 同一条待办不可重复完成（前端隐藏已完成项的勾选按钮）
- 历史记录默认展示近 7 天，分页加载（每页 20 条）
- 逾期待办排序：逾期项置顶，按创建时间升序
