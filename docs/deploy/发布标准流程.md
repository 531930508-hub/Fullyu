# 发布标准流程（Full愈 · presence）

> 适用：`presence/**` 的代码变更上线。域名/机器/端口事实源见 `docs/deploy/domains.tsv` 与 `docs/deploy/生产方案-最终版.md`；凭据见 `~/.fullyu-secrets/SERVERS.md`（不进仓库）。
> 本文只讲"怎么发"，跨项目的动作边界见全局规则「提交/推送/发布/部署/验收/回滚六词标准动作」。

## 0. 一句话

**推 `main` → GitHub Actions 自动构建并部署到 ECS**，但需要仓库变量 `ENABLE_DEPLOY=true` 才真正执行 deploy job；**推功能分支永远不会上线**。

## 1. 链路

```
push main（paths: presence/** 或 .github/workflows/ci-deploy.yml）
  └ build-check（ubuntu runner，working-directory: presence）
      pnpm install --frozen-lockfile
      shared build → prisma generate → server build → admin build → H5 build
      → miniprogram vue-tsc --noEmit → 打包 admin/h5 dist 为 artifact
  └ deploy（if refs/heads/main && vars.ENABLE_DEPLOY == 'true'）
      runner: 打 server 源码包（apps/server/src|prisma|配置文件 + packages/shared）
      scp 三个 tar 到 ECS /tmp/fullyu-ci
      ECS: 备份旧 dist → 原子替换 nginx 根
           → 解开源码包覆盖 $SERVER_PATH（打平 presence 层）
           → shared build → prisma generate → prisma db push（失败仅告警）
           → tsc 编译 → pm2 restart fullyu-api → curl 127.0.0.1:3000/api/v1/health
```

## 2. 关键事实（决定能怎么发）

| 项 | 值 |
|---|---|
| 仓库 | `git@github.com:531930508-hub/Fullyu.git`（HTTPS remote 无凭据，推送走 SSH key） |
| 部署分支 | `main` |
| 生产入口 | `presence.fullyu.cn` → 120.55.36.3 |
| 后端 | PM2 进程 `fullyu-api`，`$SERVER_PATH=/root/fullyu`，`:3000` |
| 后台静态 | `/opt/fullyu/apps/admin/dist`（nginx `:8080`） |
| H5 静态 | `/opt/fullyu/apps/miniprogram/dist/build/h5`（docker-proxy `:8101`） |
| ECS 上的源码 | **不是 git 仓库**，是从 `presence/` 打平的 rsync 副本；故用源码包覆盖而非 git pull |
| `apps/server/.env.local` | 只在 ECS 上，部署不覆盖；缺失则 deploy 直接失败 |
| 依赖变更 | workflow **刻意不跑 install**；新增/升级依赖必须先在 ECS 手工 `pnpm install`，否则编译或启动会缺包 |
| 数据库 | 仅 `prisma db push`（仓库无 migrations）；**禁止** `migrate dev` / `migrate reset`；push 失败只告警，需人工跟进 schema 漂移 |
| 测试环境 | `test-presence.fullyu.cn`（8.133.6.18，`:13000`）**目前没有 CI 通道**，只能手工发布，见 §6 |

## 3. 标准动作：发布到生产

1. **确认改动范围**：`git status`、`git log origin/main..HEAD`；只带本次改动的提交，别人的未提交改动不动。
2. **本地验证门禁**（等价于 CI 的 build-check，任一红就停）：
   ```bash
   cd presence
   pnpm install --frozen-lockfile
   pnpm --filter @fullyu/shared build
   pnpm --filter @fullyu/server db:generate
   pnpm build:server && pnpm build:admin   # admin 内含 vue-tsc --noEmit
   pnpm --filter @fullyu/miniprogram build:h5
   pnpm --filter @fullyu/miniprogram exec vue-tsc --noEmit -p tsconfig.json
   ```
3. **合并并推送**（`--ff-only`，有冲突就停下来问，不要强推）：
   ```bash
   git checkout main && git pull --ff-only
   git merge --ff-only <feature-branch>
   git push origin main          # 若 HTTPS 无凭据：git push git@github.com:531930508-hub/Fullyu.git main
   ```
4. **盯 CI**：`build-check` 绿 → `deploy` 是否出现。若 `deploy` 被跳过，说明 `ENABLE_DEPLOY` 未开：Settings → Secrets and variables → Actions → Variables。
5. **生效探针**（必做，不能只看"构建成功"）：
   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' https://presence.fullyu.cn/api/v1/health          # 期望 200
   curl -s -o /dev/null -w '%{http_code}\n' https://presence.fullyu.cn/api/v1/<新接口>          # 发布前 404 → 发布后 401/200
   curl -s -o /dev/null -w '%{http_code}\n' https://presence.fullyu.cn/admin/                  # 期望 200
   ```
   CI 日志里的 `health ok` 是必要条件，不是充分条件。
6. **汇报格式**：`目标环境 | commit | CI 结论 | 生效探针前后值 | 回滚命令 | 遗留人工项`。

## 4. 回滚

- **前端**：ECS `/tmp/admin-dist.bak-<ts>.tar.gz`、`/tmp/h5-dist.bak-<ts>.tar.gz`（每次部署自动备份），解包覆盖回去即可。
- **后端**：`/tmp/server-dist.bak-<ts>.tar.gz`（编译产物）或直接回滚 commit 重跑发布（源码包覆盖是幂等的）。
- **数据库**：不做逆向迁移；`db push` 是加列/加表为主，回滚代码时保留新列通常无害。

## 5. 常见坑

- 只推了功能分支 → 线上完全没变，别误判成"已上线"（2026-11-13 导师门户就是这个情况）。
- `origin` 是 HTTPS 且 keychain 无凭据、`gh` 未装 → 用 SSH URL 推送，不要改 remote 配置。
- ECS 内存有限：前端产物必须在 runner 构建后 scp，不能在 ECS 上 build。
- 依赖新增没在 ECS 装 → tsc 能过但运行时缺包。
- 小程序上线不走这条链路：需微信开发者工具上传 + 提交审核（人工）。
