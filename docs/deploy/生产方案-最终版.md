## 0. 一页结论

1. **目标拓扑不变**：杭州 **120.55 + 121.40 交叉主备**，上海 **8.133 只做测试**，**47.111 只留中间件后释放**；不买 ALB，切机靠 DNS。
2. **现状不是"两台主备"，是"四台各跑一段"**：在场只在 120.55；时叙 + CRM 同在 121.40；轻疗生产还在上海 8.133；47.111 只剩 Redis / RabbitMQ，但**轻疗正在连**（6379/5672 均为 ESTAB）。**四个业务的双机落地数是 0/4。**
3. **现在的单点不是"少一台备机"，是四件事叠在一起**：
   - 在场只有 120.55 一台，Redis 还是本机 `127.0.0.1`；
   - 时叙和 CRM 绑在同一台 121.40，一起挂；
   - 轻疗生产跑在**9 月 12 日的旧 jar** 上（11-16 已止血：日志轮转 + 每日备份 + 巡检，见 §0.8），但**新后端一次都没成功上线过**——11-15 晚发布后回滚，排期回到 11-22/23；
   - 47.111 的 Redis **无密码**；11-16 已在主机层加来源白名单（6379/5672 仅 8.133/120.55/121.40），但**阿里云安全组还没收口**，两层都要。
4. **双机真正的前置是三件，不是"再部署一份"**：
   - **共享 Redis**：在场有 9 处 `withLock` 调用（候补报名、券核销、审批、品牌邀请等）。DNS 切机重叠期内两台同时接流量，锁不共享 = 同一张券可能核两次。修订四说"订单号会重复"不准确：发号有库内对齐 + 撞号重试，单号不会重复；但**锁会失效**，结论不变。
   - **时叙 / CRM 的库上 RDS**：时叙现在是 121.40 本机 MySQL（1.5MB），CRM 是 SQLite（14MB）。库不共享，备机只能当摆设。
   - **定时任务单活**：在场有 `TASKS_ENABLED` 开关；时叙有 5 个定时器没有开关；轻疗有 **15 个 `@Scheduled`（11 个文件）**没有开关，只能冷备。
5. **切机窗口按 10 分钟算，不是 1–3 分钟**：阿里云 DNS 该套餐 TTL 下限 **600 秒**（实测四域名全为 600），修订四写的 60 秒做不到。切机期间旧 IP 仍会有最长 10 分钟流量，**必须共享 Redis + 同一套库**，轻疗必须"停旧再起新"。
6. **11-24 前只做两件**：**8.133 止血**（日志、备份、巡检、47.111 收口）+ **轻疗新后端上线**（原地换 jar，机器不动）。双机放到 11-24 之后，避免"换 jar + 换机"挤同一晚。**止血已于 11-16 凌晨完成**：日志、备份、巡检、文档、root 轮换、47.111 双层收口；0.7 群机器人取消（不接企微）。
7. **本轮明确不做**：自动切换、ALB、轻疗与在场共用 Redis、8.133 在轻疗未搬走前接全套测试。

### 2.3 为什么轻疗只能冷备

轻疗后端有 **15 个 `@Scheduled`（11 个文件）**：接待、会员卡、客户提醒、支付分组、预付费奖励、按摩师、低评分审批、品牌订单上报、管理端通知、JobService 等。Java 侧没有类似 `TASKS_ENABLED` 的总开关，温备会让同一批任务在两台各跑一遍。两种选择：

- **冷备（本轮）**：备机只放 jar/静态/配置，进程不启动；切换时停旧、起新、改 DNS。代价是切换瞬间有 20–30 秒启动 + 10 分钟 DNS 缓存。
- **温备（后续）**：给 15 个任务加统一开关（`fullyu.tasks.enabled=false` 或 `@ConditionalOnProperty`），改完并回归后再升级。**不在本轮做。**

### 2.4 TTL 600 对切换的硬约束

- 实测：`presence` / `teahour` / `crm` / `cityretreat` 的 A 记录 TTL 均为 **600 秒**；阿里云该套餐下限就是 600，方案原定的 60 秒做不到。
- 含义：改解析后，**最长 10 分钟内仍有客户端打旧 IP**。
- 因此：
  - 在场 / 时叙 / CRM 切机时，**两台都必须在线**、连同一套库和同一个 Redis，否则重叠期锁与任务会打架。
  - 轻疗冷备切机，旧机必须在改 DNS 前停掉；重叠期打旧 IP 的客户端会看到维护页（夜间窗口可接受）。
  - 要缩短到 60 秒以下，只有两条路：升级 DNS 套餐到支持更低 TTL 的版本，或把权威 DNS 迁到 Cloudflare。**本轮不折腾，按 10 分钟设计。**

### 2.5 为什么不用 ALB

ALB 能秒级切换，但按量计费 + 多一层组件；切换窗口实际由门店离线兜底决定（PWA 离线队列 + 纸单）。TTL 600 下 ALB 也救不了 DNS 缓存，收益更低。保留结论：**不买**。若以后要求秒级，再回头评估 ALB 或自建极小反代。

## 7. 发布与切换手册

### 7.1 四条发布通道

| 通道 | 适用 | 流程 | 回滚 |
|---|---|---|---|
| **A. CI/CD** | 在场常规版本 | push main（`paths: presence/**`）+ 仓库变量 `ENABLE_DEPLOY=true` → runner 构建 → scp → ECS `tsc` + `prisma db push` + PM2 restart + health | `/tmp/*.bak-<ts>.tar.gz` |
| **B. 源码包手工** | CI 不可用 | 打 `server-src.tar.gz` → scp → 解包 → shared build → db:generate → tsc → PM2 restart | 同上 |
| **C. dist 热替换** | 盘中止血 | 本地 build → 只 scp 对应 `dist/**/*.js` → 备份 `dist.bak-<ts>/` → 覆盖 → restart | cp 回再 restart |
| **D. 备机同步**（新增） | 双机上线后 | 同一份产物 scp 到备机 → 原子替换静态 + 覆盖 server dist → 重启备机 PM2/systemd → health | 备机保留上一版 `dist.bak-<ts>/` |

**纪律**：C 只用于开盘止血，24h 内必须补 A/B 全量，否则线上 dist 与源码不同源。

**在场后台静态**：2026-11-13 起 `presence.fullyu.cn/` 由 nginx 直接吃 `/opt/fullyu/apps/admin/dist`，**不再经过 8101 容器**。`发布标准流程.md` 里的容器 md5 校验步骤已过期，以本方案为准。

### 7.2 schema 变更检查单（每次动表必走）

1. 先备份整表：`CREATE TABLE xxx_bak<日期> AS SELECT * FROM xxx;`
2. 手写 `prisma/additive-<feature>.sql`，只加不删，先在 RDS 执行。
3. 同批改 `schema.prisma` 并 `prisma generate`。
4. 再发代码（列先于代码存在）。
5. CI 的 `db push` 只负责对齐；跑之前确认没有未合并的手工 SQL。
6. 回滚 = 回代码，不删列。

> 11-15 的漂移就是这条没走完：只改了库没合 `schema.prisma`，CI 的 `db push` 试图把库推回旧结构。修 schema 时按此单执行。

### 7.3 案例：候补退款无限重试（2026-11-12 已根治）

- 现象：4 笔测试订单每 5 分钟重试，流水号追加到 `_583`，累计 2332 条退款记录。
- 根因：`refundFull` 遇网关明确拒绝（5105）时把订单回滚成 `PAID` 再抛错；任务只 `logger.error`，条目留在 `WAITING`，无计数、无退避、无上限。
- 四道闸：失败计数 + 指数退避（5/15/60/360/1440 分钟）；5105/5106 一次即停并标 `[需人工]`；连续 6 次停；`REFUNDING` 交给对账任务，不重复发起。
- 另补：退款前置检查 `PROCESSING/UNKNOWN`；对账封顶 12 次；强制退款按剩余可退金额路由；结课扫描补「今天及以前结课」。
- 验证：`waitlist-refund-retry.spec.ts` 6/6；线上两轮零 ERROR；最坏从 583 条/单降到 1–2 条/单。
- **可靠性基线**：所有定时任务必须「有上限 + 有退避 + 有转人工出口 + 有告警」。

4. **切解析**：`aliyun alidns UpdateDomainRecord --RecordId <id> --RR <rr> --Type A --Value <备机IP> --TTL 600`。

6. **回切**：解析改回 + 任务开关反向 + 各自 restart；全程双方进程保持运行（轻疗除外，冷备需先起旧机）。
7. **复盘**：记录耗时、失败点、门店反馈；连续两次演练通过后再考虑自动探测。

### 8.1 仍然有效的现场经验（从修订四保留）

- **证书同步**：120.55 的 acme.sh 续期后由 `sync-fullyu-cert.sh` 推给 8.133；`authorized_keys` 里 `from="..."` 与密钥类型之间必须是**空格**，写成逗号整行失效，表现为"密钥给了但一直 Permission denied"。
