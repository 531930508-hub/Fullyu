## 2. 数据库（生产 MySQL，手工执行）

仓库内 `prisma/migrations` 是开发 SQLite 方言；生产按目录约定手写 DDL：
`deploy/mysql/20261115-member-discount-crm-profile-version.sql`

| 项 | 内容 |
|---|---|
| 演练 | 生产机 `teahour_ddl_check` 临时库导入 `customers/orders/order_items` 结构后跑通脚本，再删库 |
| 变更 | `customers.crm_profile_version`（int，默认 0）；`orders.member_discount_per_cup_cents / member_discount_cups / member_discount_cents`；`order_items.member_discount_cents`（均 int 默认 0） |
| 顺序 | 先 DDL（纯加列，旧代码忽略新列）→ 再同步 dist 并重启 |
| 数据 | 执行前 orders 6 行、customers 2 行；加列后各列全 0，无既有单被改写 |
| 回滚 | `ALTER TABLE customers DROP COLUMN crm_profile_version; ALTER TABLE orders DROP COLUMN member_discount_per_cup_cents, DROP COLUMN member_discount_cups, DROP COLUMN member_discount_cents; ALTER TABLE order_items DROP COLUMN member_discount_cents;`（先回滚 dist 再删列，避免新代码缺列） |

> 迁移目录名是 `20261118100000_customer_crm_profile_version` / `20261118110000_member_discount`（生成脚本时的日期），
> 与生产 DDL 文件名 `20261115-*` 不一致；生产以 `deploy/mysql` 为准，迁移目录只服务本地 SQLite 开发。

## 4. 部署

| 步 | 内容 |
|---|---|
| 备份 | `/opt/teahour/backups/release-20261115-1205/`：`teahour-db-*.sql.gz`（19K，`gzip -t` 通过）、`app-dist-*.tgz`（1.6M，server/dist + prisma + admin/dist + packages dist + h5） |

| H5 | `rsync -az --delete apps/miniprogram/dist/build/h5/` |

## 7. 遗留 / 风险

- 资料同步是「CRM 版本更新才回灌」：本地刚保存但 CRM 尚未返回更高 `profileVersion` 时不会被旧值覆盖；CRM 不可用时只记 `资料回写会员中心失败` 警告，本地编辑不丢，但没有重试队列。
- `savedCents` 依赖订单落库的 `member_discount_cents`，历史单为 0（不追溯）。
- 头像推 CRM 时依赖公网 `ASSET_BASE_URL`；未配置时不推 `avatarUrl`（避免 localhost 地址）。
