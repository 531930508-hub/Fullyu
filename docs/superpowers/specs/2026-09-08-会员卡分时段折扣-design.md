# 会员卡分时段折扣率 — 设计文档

> 日期：2026-09-08 ｜ 状态：已确认，待实现
> 关联分析：《Full愈 门店忙闲与预约行为分析报告》（2026-08-27，忙闲 5 级星级 → 差异化定价）

## 1. 背景与目标

现有会员折扣是「课程 × 卡类型 → 固定折扣百分比」（`CourseMemberDiscount`），没有时段维度。
数据分析显示两店忙闲差异显著（周末下午峰值、每日 10–12 点闲时），需要按忙闲时段做差异化定价：
峰值时段取消折扣甚至加价，闲时给深折引流。

目标：后台可配置「会员卡分时段折扣规则」，支持星期、一天内时间段、日期范围（覆盖节假日场景）的
自由组合，下单询价时按预约开始时间自动匹配。

## 2. 已确认的需求决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 配置维度 | 门店 × 卡类型；**两者均支持多选，不选 = 全部**。显式包含该门店的规则优先，"全部"规则兜底（新开门店自动继承全局规则） |
| 2 | 时段判定口径 | 按**本单预约开始时间**整单判定（不做占用时长分段计价） |
| 3 | 冲突处理 | **手动优先级**：列表拖拽排序，越靠前越优先；先按门店特异性分组（显式门店 > 全局），组内按 priority |
| 4 | 兜底链 | 时段规则 → 现有 `CourseMemberDiscount` 固定折扣 → 原价 |
| 5 | 节假日 | 不做节假日库，用规则的**日期范围**手动配（如 10-01 ~ 10-07） |
| 6 | 折扣动作 | 两种：**百分比折扣率**（50–200；100=原价，85=8.5折，115=加价15%）；**按时长固定价**（轻疗项目：如 30min=133元、60min=266元、90min=399元） |

## 3. 数据模型（Prisma）

```prisma
// 会员卡时段折扣动作类型
enum TimeDiscountActionType {
  PERCENT           // 百分比折扣率
  FIXED_BY_DURATION // 按服务时长取固定价
}

enum TimeDiscountRuleStatus {
  ENABLED
  DISABLED
}

// 会员卡分时段折扣规则（门店/卡类型可多选，空=全部；手动优先级匹配）
model MemberTimeDiscountRule {
  id          String       @id @default(cuid())
  name        String       // 规则名（后台识别用，如"周末峰值"）
  orgIds      Json         @map("org_ids")      // string[]，适用门店 Organization.id；空数组 = 全部门店（兜底）
  cardTypes   Json         @map("card_types")   // MemberCardType[]；空数组 = 全部卡类型
  priority    Int          // 数字越小越优先；同特异性分组内排序（后台拖拽调整）
  weekdays    Json         // number[] [1-7]（1=周一…7=周日）；空数组 = 不限星期
  timeRanges  Json         @map("time_ranges")  // [{start:"HH:mm", end:"HH:mm"}]，含头不含尾，start<end（不支持跨午夜）；空数组 = 全天
  validFrom   DateTime?    @map("valid_from")   // 生效起始日（含，按日期比较）；空 = 不限
  validTo     DateTime?    @map("valid_to")     // 生效截止日（含）；空 = 长期有效
  actionType  TimeDiscountActionType @map("action_type")
  discountPercent Int?     @map("discount_percent") // PERCENT 时必填，50–200
  fixedPrices Json?        @map("fixed_prices")     // FIXED_BY_DURATION 时必填：[{minutes:Int, price:Int(分)}]，minutes>0、price>=0、minutes 不重复
  status      TimeDiscountRuleStatus @default(ENABLED)
  remark      String?
  createdAt   DateTime     @default(now()) @map("created_at")
  updatedAt   DateTime     @updatedAt @map("updated_at")

  @@index([status])
  @@map("member_time_discount_rules")
}
```

不建 org 外键关系（orgIds 为数组），由应用层校验门店存在性。

**Order 表**：新增可空字段 `hitTimeRuleId String? @map("hit_time_rule_id")`，记录命中的规则，
用于对账与排查。金额单位与现有运行时口径一致（Decimal 元、计算时 Number 元）：`fixedPrices.price` 以元存储，支持两位小数。

**匹配纯函数放 `packages/shared`**（沿用审批流引擎模式：前端预览与后端落库调用同一份代码，
单测集中在 `apps/server/test/*.spec.ts`）。

## 4. 计价逻辑（PricingService）

`getMemberDiscount(userId, courseId, basePrice)` 扩展为
`getMemberDiscount(userId, courseId, basePrice, appointmentStart: Date)`：

```
1. 查用户当前有效会员卡（现有逻辑不变）；无卡 → 无折扣
2. course → venue → orgId 定位门店（venue.orgId 为空时只匹配全局规则）
3. 候选规则 = status ENABLED
   且 (validFrom 空 或 appointmentStart 日期 >= validFrom)
   且 (validTo 空 或 appointmentStart 日期 <= validTo)
   且 (orgIds 空 或 包含 orgId)
   且 (cardTypes 空 或 包含 card.type)
4. 排序：特异性（orgIds 非空在前）→ priority 升序
5. 逐条匹配：appointmentStart 的星期 ∈ weekdays（或 weekdays 空）
   且 HH:mm 落在任一 timeRange（含头不含尾；timeRanges 空 = 全天）
6. 第一条命中规则执行动作：
   - PERCENT：discountAmount = basePrice × (1 − discountPercent/100)
     （>100 时 discountAmount 为负 = 加价；priceAfterDiscount = basePrice − discountAmount，下限 0）
   - FIXED_BY_DURATION：m = 本单服务时长（分钟）
     在 fixedPrices 中查 minutes == m：
       命中 → priceAfterDiscount = fixedPrice，discountAmount = basePrice − fixedPrice
       未命中（无该时长或时长未知）→ 本条规则视为未命中，继续匹配下一条
7. 全部未命中 → 回退 CourseMemberDiscount（现有逻辑）→ 无配置 → 原价
8. 返回 { cardType, discountPercent | null, discountAmount, hitTimeRuleId | null, priceAfterDiscount }
```

**服务时长 m 的来源**：`Course.duration`（单节时长/分钟，预约型轻疗课程必填）。
`duration` 为空时 FIXED_BY_DURATION 规则一律不命中（PERCENT 规则不受影响）。

**调用点（3 处，均传入预约开始时间）**：
- `order/enrollment.service.ts` → `quote()`：询价展示
- `order/enrollment.service.ts` → `enroll()`：下单锁价（事务内以最新规则重算）
- `waitlist/waitlist.service.ts`：候补入队锁价

**appointmentStart 的取值**：预约型课程 = 用户所选预约时段的开始时间；
单次/周期课 = 本次上课的开始时间（startDate + startTime 合成的当次开课时刻）。

**锁价语义不变**：询价/下单时算好即锁定，支付超时释放后重新询价按最新规则计算；
已生成订单不随规则修改/停用回溯变化。

## 5. 后台界面（apps/admin，销售 → 会员卡管理 → 新增「时段折扣」标签页）

1. **规则列表**：筛选（门店、卡类型、状态）；表格列 = 拖拽把手+优先级、规则名、门店（空显示"全部门店"）、
   卡类型、星期、时间段、日期范围、折扣动作（`85%` 或 `按时长固定价` 悬浮展示价目）、状态、操作（编辑/停用/启用/删除）。
   拖拽排序保存 priority；删除仅限无订单引用（`hitTimeRuleId`）的规则，否则只允许停用。
2. **新建/编辑抽屉**：规则名；门店多选（不选=全部，界面明示"不选 = 全部门店（新店自动生效）"）；
   卡类型多选（不选=全部）；星期多选 chips（不选=每天）；时间段多行（HH:mm–HH:mm，可加多段，start<end 校验）；
   日期范围（可空=长期）；折扣动作单选：
   - 百分比：输入 50–200，提示文案"100=原价，<100 打折，>100 峰时加价"
   - 按时长固定价：时长(分钟)+价格(元) 行编辑器，可增删行
3. **一周总览预览**（编辑抽屉底部 + 列表页顶部入口）：选定门店×卡类型后，
   按当前全部启用规则实时演算「星期 × 时段」每格最终生效结果
   （百分比显示 `85%`；固定价显示 `¥133/30′`；未命中显示回退结果 `90%†`/`原价`），
   hover 显示命中规则名，用于保存前发现规则打架。演算直接调用 `@fullyu/shared` 的匹配纯函数
   （与后端落库同一份代码，沿用审批流"前后端各调一次"模式），不另做 preview API、不前端重写逻辑。
   优先级调整用 ↑/↓ 按钮（现有后台无拖拽依赖，不新增）；筛选激活时禁用调序，避免局部视图误改全局顺序。
4. **权限**：沿用 RBAC 现有模式，在销售模块下新增权限点（时段折扣查看/编辑），随会员卡片页面权限投影。

## 6. 小程序端

询价/确认页价格明细增加时段折扣展示：
- PERCENT：沿用现有"会员折扣"行，标注时段（如"闲时 7 折"）
- FIXED_BY_DURATION：会员价直接展示固定金额（如"会员时段价 ¥133"）
无命中时展示不变。

## 7. 边界与错误处理

- 校验：timeRange `start < end`；`discountPercent ∈ [50,200]`；`fixedPrices` 非空、minutes 为正且组内唯一、price ≥ 0；
  PERCENT 必填 discountPercent、FIXED_BY_DURATION 必填 fixedPrices（互斥校验）
- 时间比较一律含头不含尾；日期范围比较按 Asia/Shanghai 自然日（含两端）
- 不支持跨午夜时间段（营业时间 10:00–23:00，无此场景）
- 规则停用/修改不回溯已锁价订单
- venue.orgId 为空（未挂门店的场地）：只匹配全局（orgIds 空）规则
- 候选规则一次性查出内存匹配（单店规则量级 <100，无性能问题）；不做缓存层（YAGNI）

## 8. 测试要点

- 匹配算法单测：优先级排序、门店特异性（显式 > 全局）、星期/时间段边界（14:00:00 命中、17:59:59 命中、18:00:00 不命中）、
  日期范围含两端、FIXED_BY_DURATION 时长命中/未命中/课程无时长、PERCENT 加价（>100）金额计算、
  兜底链（规则未命中 → 固定折扣 → 原价）
- Admin API：CRUD、拖拽排序持久化、删除限制（被订单引用时拒绝）、preview 演算接口
- 集成：quote/enroll/waitlist 三调用点传入 appointmentStart 后金额正确、订单落 hitTimeRuleId

## 9. 不在本期范围（YAGNI）

- 法定节假日自动日历
- 通用促销规则引擎（满减、组合优惠等）
- 按占用时长分段计价
- 产品（课程）级时段规则、非会员的时段定价
