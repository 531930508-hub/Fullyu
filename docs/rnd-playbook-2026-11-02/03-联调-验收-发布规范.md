# 联调、验收与发布规范

> 用途：把“能跑”变成“有证据的闭环”。重点覆盖支付、微信登录/隐私、视觉对齐、测试分级、部署与回滚。  
> 适用：时叙、在场及后续 Full愈 系项目。外部接口、真实扣款、发布仍需单独授权。

## 1. 功能契约（一页就够）

任何新功能/改造，先写这一页；小修复可压缩成 5 行，但不能没有。

```text
功能：
经营目的：谁在什么场景完成什么任务；成功/失败分别是什么
入口：顾客端 / 门店端 / 总部后台 / 服务端任务
角色与范围：身份 × 动作 × 对象 × 字段；ALL/NONE/门店集合
数据：权威表、约束、快照、TTL、历史保留
状态机：初始 → 处理中 → 成功/失败/未知 → 恢复/关闭
外部依赖：渠道、设备、平台配置、密钥位置
异常：空/载/错/离线/重复/超时/并发/权限
验收：Given/When/Then + 证据级别
不做：明确非目标，防止顺手扩大
```

> 需求清楚时按合理默认推进；只有会改变价格、退款、权益、结算、采购职责、数据归属的问题才集中问用户。

## 2. 支付专项

支付返工的根因通常不是代码能力，而是**契约没固化、状态没分开、证据只看前端**。切 live 前逐项打勾。

### 2.1 先把八个问题问清

| # | 问题 | 必须得到 | 失败后果 |
|---|---|---|---|
| 1 | 产品号 / 交易类型 | 小程序 JSAPI 用哪个 `trade_type`；正扫/反扫是否支持 | 写错类型，一直 `23000004` |
| 2 | 商户与门店映射 | 每个门店的子商户号；缺映射时 fail-closed | 收到默认商户，账对不上 |
| 3 | AppID / openid | 主/子 AppID、openid 来源、`sub_appid` 是否绑定 | 预下单成功但拉起失败 |
| 4 | 回调地址 | 公网 HTTPS、路由存在、验签方式、原始 body | 回调 404/验签失败，订单不落账 |
| 5 | 密钥 | 商户私钥、平台公钥、回调密钥的位置与权限 | 验签失败/无法启动 |
| 6 | 结算账户 | 默认结算账户是否配置 | `22000003` |
| 7 | 退款能力 | 退款接口、必填原交易字段、部分退款、到账时间 | 退款占用不释放 |
| 8 | 查询/对账 | 查询接口版本、按什么号查、多久查一次 | 超时/丢回调无法恢复 |

**能力探测**：先用只读/最小请求确认支持范围，再写 UI。不要把“改字符串试试”当成探测；不要把“文档里没写”当成“不能用”，也不要把“文档里写了”当成“已开通”。

### 2.2 三个状态机分开

```text
订单：created/unpaid → paying → paid → preparing → ready → delivered
                       ↘ cancelled / closed
支付意图：created → pending → succeeded / failed / unknown / closed
退款：occupied → processing → succeeded / failed / released / unknown
```

硬规则：

- 只有**验签回调**或**渠道查询确认**才能把订单改为 paid；前端 `requestPayment` 成功不算到账。
- 重复回调必须幂等：返回成功，但不重复记账/出杯贴/发券。
- 金额、单号、商户必须匹配；不匹配拒绝并写人工核对。
- 支付失败/取消要释放库存与券；超时/网络丢失属于 unknown，不能直接当失败释放。
- 退款用稳定退款单号；unknown 保留占用并可重试同一单号；明确业务拒绝才释放。
- 失败后迟到的成功回调不能静默落账；进入人工核对。
- 事务、幂等、补偿/对账是三件事，不能互相冒充。

### 2.3 错误分类（比“成功/失败”多两档）

| 类别 | 例子 | 处理 | 用户提示 |
|---|---|---|---|
| 成功 | `00000000`、`00000100 下单成功` | 继续流程 | 正常 |
| 明确业务拒绝 | `23000004 交易类型不支持`、`22000003 未配置账户`、`10000000 字段不能为空`、`101 付款码无效` | 释放占用/不重试；修配置或换方式 | 可读原因，不冒 500 |
| 结果未知 | 网络超时、响应丢失、`20000000 重复交易`、5xx | **保留占用**；按原单号查询/重试 | “处理中/结果待确认” |
| 鉴权/配置 | 922 未签名、验签失败、缺密钥 | fail-closed；告警 | “服务暂不可用” |

实现要求：业务错误用返回值表达（`ok:false` + 原文），不要全部抛异常；未知才抛/保留；原始错误码只进服务端日志。

### 2.4 支付测试矩阵

| # | 场景 | 期望 | 证据 |
|---|---|---|---|
| 1 | 预下单成功 | 返回可拉起参数；订单仍 unpaid | 响应 + DB |
| 2 | 用户取消支付 | 订单 unpaid；可重试/取消；不扣库存 | 端上 + DB |
| 3 | 支付超时/断网 | 进入 unknown；查询后收敛；不重复扣 | 日志 + 查询 |
| 4 | 正常回调 | 订单 paid；流水/杯贴一次 | 回调 + DB |
| 5 | 重复回调 | 返回成功；不重复记账/打印 | 重放 + DB |
| 6 | 乱序回调（先成功后失败） | 失败不覆盖成功；写人工核对 | 重放 |
| 7 | 金额不符 | 拒绝；告警；不改单 | 篡改报文 |
| 8 | 验签失败 | 拒绝；不落账 | 篡改签名 |
| 9 | 门店映射缺失 | fail-closed；不下单到默认商户 | 删映射 |
| 10 | 下单后售罄 | 支付前/后拒绝或退款；库存一致 | 并发下单 |
| 11 | 下单后改价 | 以服务端新价为准或拒绝；不按旧价收 | 改价 |
| 12 | 取消未支付单 | 释放库存/券；可再来一单 | 端上 + DB |
| 13 | 全额退款 | 占用→成功；流水冲减；库存/权益按规则 | DB + 渠道 |
| 14 | 部分退款 | 不超可退；逐行数量校验；券分摊正确 | DB |
| 15 | 退款明确拒绝 | 释放占用；可改方式重试 | 响应 + DB |
| 16 | 退款重复提交 | 同退款单号幂等；不二次退 | 重放 |
| 17 | 退款网络未知 | 保留占用；查询/重试同单号 | 断网 |
| 18 | 失败后迟到成功 | 不静默落账；人工核对 | 重放 |
| 19 | 进程重启 | 未完成意图可恢复；回调可补 | 重启 |
| 20 | 并发支付/退款 | 条件更新；只成功一次 | 并发脚本 |
| 21 | 渠道不支持的方式 | UI 不展示；接口返回可读拒绝 | 能力探测 |
| 22 | 反扫假付款码 | 可读“付款码无效”；不 500 | 真实网关 |
| 23 | 真实小额 JSAPI | 真实扣款/落账/回调 | **单独授权** |
| 24 | 真实退款 | 到账/流水/占用释放 | **单独授权** |

> 23/24 没有授权就不做，也不能用 mock 结果代替；在交付表里写“未测：真实扣款/退款”。

### 2.5 对账与恢复

- 每日/定时查询 `pending/unknown` 意图，按渠道状态收敛；不要只等回调。
- 退款 unknown 保留占用，提供“查询/重试”入口；不要自动释放。
- 差异要有凭证：渠道流水号、本地单号、金额、时间、处理人。
- 报表口径与订单/退款/费用统一；重复消息不重复记账。

## 3. 微信登录与隐私专项

### 3.1 平台配置（代码替代不了）

| □ | 配置 | 说明 |
|---|---|---|
| □ | 用户隐私保护指引 | 只声明实际用到的：手机号、位置、头像/昵称、相册（仅写入） |
| □ | 不声明摄像头 | `scanCode` 是微信扫码，不算摄像头 |
| □ | 不声明相册读取 | 只用 `saveImageToPhotosAlbum` 时声明“仅写入” |
| □ | 手机号快速验证 | 主体/类目/能力开通 |
| □ | 域名白名单 | request/upload/download 合法域名 |
| □ | 法务页 | 用户协议、隐私政策可访问，内容与实际收集一致 |
| □ | 审核文案 | 无“微信登录/微信手机号”，无默认同意，无过度声明 |

### 3.2 代码检查

| □ | 项目 | 要求 |
|---|---|---|
| □ | 主动勾选 | 默认 false；未勾选不渲染 `getPhoneNumber` |
| □ | 原生隐私 | 不注册 `onNeedPrivacyAuthorization`，保留官方弹窗 |
| □ | 登录链路 | `wx.login` code + 手机号 code；服务端换 openid/手机号 |
| □ | token | stable_token 缓存、提前过期、并发单飞、失效刷新一次 |
| □ | 错误映射 | 40029/40163/41008→400；45011→429 + 一次退避；配置/网络→503 |
| □ | 防冒充 | 真实模式拒绝显式手机号；H5 不开放手机号登录 |
| □ | 退出 | 只清本地；服务端数据保留；重登可恢复 |
| □ | 限流 | 自家登录限流与微信 45011 分开处理 |

### 3.3 验收

- 单测：错误映射、45011 重试、显式手机号拒绝。
- 探针：无效 code 期望 400/40029；不要用真实用户。
- 真机：取消、拒绝隐私、未声明手机号、正常登录四条路径。
- 审核：提审前 grep 文案；确认隐私指引已通过。

## 4. 视觉对齐专项

### 4.1 基线

- 有 Demo/设计稿/在场成熟页面时，**原样引入其样式层**，不要边看边自写。
- 先做“屏幕 × 状态”清单：首页、茶单、详情、购物袋、结算、支付、订单、回执、我的、分享、登录、空/错/载。
- 对照物是基线截图，不是自写 UI 截图。

### 4.2 token

| 类别 | 规则 |
|---|---|
| 字族 | 界面无衬线 / 标题品名衬线 / 码等宽；不新增第四套 |
| 字号 | 页面标题 26、区块 18、弹层 18、分享 16、商品名 14/详情 20 |
| 字距 | 0.05 / 0.06 / 0.12 / 0.18em；禁 0/负值；挤就重排，不压字 |
| 颜色 | 标题色、正文色、交互色、系列图色分开；正文不用标题色 |
| 间距/圆角 | 用现有 token；不出现零散魔法值 |

### 4.3 验收

- 390×844 与 360×640 两档截图；后台再加 1280/1440/768。
- computed style 检查 `font-family`、`font-size`、`letter-spacing`、颜色。
- 同一位置被退回第二次时，**停止自创**：直接照搬参考实现的几何与计算方式；第 2 版必须附对照图。
- 改样式源文件后重新生成产物；不要手改生成文件。

## 5. 测试矩阵与证据分级

### 5.1 测试层级

| 层级 | 用来证明 | 不能证明 |
|---|---|---|
| 单元测试 | 纯逻辑：分桶、字距、日期、金额分摊、错误映射 | 页面、真机、外部通道 |
| 集成测试 | API + 真实 DB + 权限 + 状态机 | 真机授权、渠道真实扣款 |
| 浏览器 UI | 布局、交互、路由拦截的异常态 | 微信原生能力 |
| 开发者工具 | 编译、WXML/JS、部分原生 API | 真机隐私/支付/相册 |
| 真机 | 微信授权、支付、扫码、分享、安全区 | 生产全量/并发 |
| 真实通道 | 真实扣款/退款/回调/打印 | 其他未测渠道 |

### 5.2 必测维度

| 维度 | 样本 |
|---|---|
| 非默认配置 | 第三家店、新商品、新价格/描述、不同退款门槛 |
| 持久性 | 刷新、重开、重登、重启、恢复 |
| 隔离 | 顾客 A/B、员工 A/B、店 A/B、零门店 |
| 异常 | 断网、超时、401/403/404/409/500、空结果 |
| 时序 | 双击、重复回调、乱序、延迟、响应丢失 |
| 并发 | 两人审批、两店领取、退款与出餐、重复导入 |
| 时间 | 时区、跨日跨月、营业日、TTL 边界 |
| 边界 | 分页/截断/大数/空数组/超长文案 |
| 跨端 | 后台改配置 → 小程序新会话 → 实际执行 → 账/库存 |
| 真实能力 | 微信真机、支付沙箱/真实小额、打印设备 |

### 5.3 证据分级

- **E0** 方案/静态原型。
- **E1** 源码存在，静态检查/类型/构建。
- **E2** 隔离环境真实 DB + API/跨端闭环，外部可 mock。
- **E3** 目标部署形态下故障、并发、安全、恢复、容量。
- **E4** 授权后的真实集成/真机/试点。

每条证据写：日期、源码版本/提交、命令、退出码、环境、数据隔离方式、产物、未测项。**mock 只证明替身契约；开发者工具不等于真机；上传开发版不等于体验版/审核/发布。**

### 5.4 测试数据

- 默认用临时/隔离数据库；不隐式使用生产 `DATABASE_URL`。
- UI 异常态优先用路由拦截/合成数据，不写业务库。
- 真实渠道测试单独授权，记录金额与单号；不把凭证写进日志/截图/记忆。

### 6.3 部署

| □ | 项目 | 要求 |
|---|---|---|
| □ | 顺序 | shared → integrations → server → admin → H5 |
| □ | schema | 改 schema 必须 `prisma generate`，再重启 |
| □ | rsync | `--delete` 前确认排除校验文件/上传目录；或构建自带 |
| □ | 重启 | `systemctl restart` 后 active |
| □ | 健康 | `/api/health` 200；渠道模式正确 |
| □ | 静态 | 校验文件看 Content-Type/Length/正文；图片/JS 实际 200 |

| □ | 读回 | 关键接口/页面重新请求，不只看构建 |

### 6.4 发布层级（小程序）

```text
开发版本（miniprogram-ci 上传）
  → 体验版（公众平台手动选版本）
  → 提交审核（公众平台手动）
  → 正式发布（公众平台手动）
```

- 上传成功只代表开发版本存在；**不能写“已发布”**。
- 体验版切换、提审、发布没有 CI 接口，必须人工。
- 每次记录：版本号、描述、zip/整包/代码文件数、上传时间、体验版是否切换。

## 8. 事故库（复发最多的八个）

| 事故 | 根因 | 固定规则 |
|---|---|---|
| `00000100` 被判失败 | 用“非 00000000 即失败” | 成功码表显式列出；业务拒绝/未知分开 |
| `T_NATIVE` 一直 23000004 | 产品/子商户未开通，误以为参数错 | 先能力探测，再写 UI；不支持就不展示 |
| 退款占用不释放 | 缺 `org_req_date`，业务拒绝被当未知 | 每个接口列必填字段；明确拒绝释放，未知保留 |
| 商品挪序 500 | 部署漏 `prisma generate` | schema 变更后必须 generate + 重启 |
| 校验文件 200 但是 HTML | 只看状态码 | 同时看 Content-Type/Length/正文 |
| 小程序连 localhost | 无 `VITE_API_BASE` 重建 | 产物 grep 线上域名 |
| H5 仍旧字体 | 只上传小程序 | 三端版本表；未部署显式标旧 |
| 在场误删共用表 | 按 migrate diff 清理未知 schema | 全库备份；未知表只增不删 |
