# 协作协议：如何少提醒、少返工

> 目标：用户只做经营决策和授权，不再逐项提醒工程完整性；AI 主动盘点、主动验收、主动报缺口。  
> 这份文档同时约束人和 AI：人给目标与边界，AI 给闭环与证据。

## 1. 默认分工

| 事项 | 用户 | AI |
|---|---|---|
| 经营口径 | 定价、退款规则、券是否返还、采购职责、数据归属 | 把口径落成配置/状态机/测试 |
| 视觉方向 | 提供基线/参考图；确认品牌方向 | 逐屏对照、token 化、截图验证 |
| 工程完整性 | 不需要提醒 | 自动检查管理配置、三端、权限、持久化、异常、恢复 |
| 外部能力 | 提供账号/授权/平台配置 | 列前置条件、探测、接适配层、标真实边界 |
| 发布 | 单独授权 | 准备可发布产物、列手工步骤、不擅自发布 |
| 验收 | 看证据与结果 | 给 E 级别、命令、截图、未测项 |

一句话：**用户说“做什么、为什么”，AI 负责“还差什么、怎么证明”。**

### 不可越过的红线（原样保留）

- “密钥和凭证不进源码、日志、报告、截图或记忆；测试使用隔离合成数据，不隐式使用已有业务库。”
- “未经明确授权，不接真实支付/打印/会员/外卖/在场接口，不写生产数据、不改 schema/实际权限/部署，不提交、push、发布或外发内部资料。Demo 或交付包授权不是上线批准。”

## 2. 需求输入：一句话就够

用户不需要写 PRD。推荐格式：

```text
目标：一句话说清要解决什么
参考：有就发图/链接/页面；没有就说“按现有基线”
范围：只改哪端/哪页；不改什么
必须：这次一定要有的 1–3 点
不做：明确不碰的
授权：只改代码 / 可上传开发版 / 可部署 / 可真实支付（分别写）
```

例子：

> “加购太生硬，参考同业做得丝滑一点。只改小程序，不动后台。可以上传开发版，不发布。”

AI 应自行补齐：首加弹层、复购复用、飞杯/抖动/提示/震动、定时器清理、两档截图、单测、构建、上传、体验版手工步骤；**不要反问“要什么动画”**。

## 3. AI 首轮回复：五行以内

需求清楚时，不要先写长 PRD，也不要问“是否继续”。首轮给：

```text
理解：我按……做（一句话）
基线：以……为准；不改……
影响：涉及……端/接口/数据
默认项：这轮自动包含……
只问：唯一会改变经营口径的问题是……
```

没有经营口径问题时，直接开工；用任务列表展示进度，不要求用户逐步确认。

## 4. 什么时候必须问

只问四类：

1. **会改变钱/权益/职责**：退款是否返券、部分退款、结算主体、采购权限、会员权益、数据归属。
2. **不可逆外部动作**：真实扣款、真实退款、部署、提审、发布、发消息、外发资料。
3. **没有基线且存在多个合理方向**：视觉方向、品牌语气、信息架构；给 2–3 个方案 + 推荐，不要开放式追问。
4. **缺少必要访问/凭证**：账号、密钥、平台权限；只说明需要什么，不要求把密钥发到聊天。

## 5. 什么时候不该问

以下问题默认“是”，不要浪费一轮：

- 要不要做分享、隐私协议、空态、错误态、加载态、防重复、权限负向、持久化、审计？
- 要不要写测试、跑构建、做截图、检查真机？
- 要不要处理断网、超时、售罄、门店停业、登录过期？
- 要不要统一字体/字距/颜色 token？
- 要不要记录未测项和回滚方式？
- “要不要我继续？”——需求清楚就继续。

## 6. 默认交付报告

每次收尾用这个结构，先结果后细节：

```text
完成：做了什么，涉及哪些端/数据
证据：E 级别 + 命令/截图/接口/DB；哪些是真机/真实通道
未完成：没做的、没测的、被阻塞的
需要你做：公众平台设体验版/提审/隐私指引/域名等手工步骤
风险/下一步：按优先级，最多 3 条
文件：可打开的文档/产物链接
```

禁止：

- 用“页面可用/测试数量/构建成功”代替业务完成。
- 把“上传开发版”写成“已发布”。
- 把 mock/浏览器/开发者工具写成真实通道/真机。
- 把“源码存在”写成“已运行通过”。
- 把“本次审计发现”写成“已修复”。

## 7. 变更控制：不推翻原设计

用户的要求是底线：

> “你在UI和各种功能交互展现上不要乱发挥，你不能推翻原来的页面样式和功能设计去发挥。你在那个基础上，如果有不合理的可以做微调。如果有不够的可以做一定的补充。但是你不能从头到尾给我做一套新的。”

执行规则：

1. **先找基线**：V7 Demo、在场页面、现有生产页、已批准设计稿。
2. **先列对照表**：屏幕 × 状态 × 功能；缺什么补什么，不重画。
3. **只做两类改动**：不合理处微调、不够处补充；新设计必须单独提出并确认。
4. **同一位置被退回两次**：停止自创，直接照搬参考实现的几何/计算方式；第 2 版附对照截图。
5. **涉及钱/权限/数据**：先说明影响面和回滚，再动。
6. **不顺手扩大**：修 A 不重构 B；需要重构另开任务。

## 8. 常用指令（下次直接复制）

### 新功能 / 改造

```text
按 docs/rnd-playbook-2026-11-02/ 执行。
先给：基线对照表、功能契约一页、默认项清单；再实现。
默认项（分享/隐私/安全区/空错载/反馈/字体/权限/持久化）不要问我，直接做。
只有会改变经营口径的问题才问。收尾给证据表和未测项。
```

### 修 bug

```text
先复现并写失败测试，再修根因；不要先打补丁。
给我：根因、影响面、最小修改、回归范围、证据。
不要删断言迎合实现，不要把 catch 后显示成功。
```

### 支付 / 外部通道

```text
先做契约表 + 能力探测 + 状态机 + 错误分类，再写 UI。
成功码、明确业务拒绝、结果未知分开；退款/回调/重复/迟到全进矩阵。
切 live、真实扣款、真实退款分别需要我明确授权。
```

### 视觉对齐

```text
以 X 为唯一基线。先列屏幕×状态对照表，再原样引入样式层，只做必要适配。
不要自创几何；同一位置第二次退回就照搬参考实现。
给 390×844 与 360×640 截图 + computed style（字族/字号/字距/颜色）。
```

### 发布

```text
提交、构建、上传、部署、提审、发布分别授权，不要串成默认动作。
给我三端版本表（server/admin/H5/小程序）、包体、产物名、体验版是否切换、回滚方式。
H5 未部署就明确写“仍旧版”。
```

### 只审计

```text
只读调查，不改代码/数据/配置/部署。
给证据、风险、优先级和整改建议；修复另开授权。
```

## 9. 反模式清单

| 反模式 | 后果 | 替代动作 |
|---|---|---|
| 页面能打开 = 完成 | 支付/权限/异常全漏 | 按闭环与证据表验收 |
| 参考 = 灵感 | 三端返工 | 基线原样引入 + 对照表 |
| mock = 真实 | 上线才发现通道不可用 | 标 E 级别；真实通道单独测 |
| 测试数量 = 质量 | 测了无关紧要的，漏了钱/权限 | 按风险矩阵选测试 |
| 截图 = 真机 | 隐私/支付/相册全没验 | 真机清单 |
| 上传 = 发布 | 用户看不到新版本 | 开发版/体验版/审核/发布四层分开 |
| 隐藏菜单 = 权限 | 直接 URL 越权 | 四维权限 + 直接 HTTP |
| catch 后显示成功 | 失败冒充成功 | 错误诚实；未知保留 |
| 内存 = 持久化 | 重启丢单/丢草稿 | 权威库 + 恢复 |
| 先写后补测试 | 测试只证明实现，不证明需求 | 先红后绿 |
| 用户没提 = 不需要 | 分享/隐私/反馈反复补 | 默认清单 |
| 改一处 = 只影响一处 | shared/schema/部署连锁故障 | 影响矩阵 + 回归 |

## 10. 预警信号

出现这些话时，立即停下重读基线/清单，不要继续打补丁：

- “还是不对”第二次 → 停止自创，照搬参考几何。
- “我不是说过吗” → 查记忆与清单，补默认项，不要解释。
- “你怎么又……” → 找根因，不要换一种补丁再试。
- “这个也要我提醒？” → 把该能力写进默认清单。
- “不要乱发挥” → 回到现有结构，只做微调/补充。

## 11. 一次对话的推荐节奏

### 小修复（≤半天）

```text
5 行根因/方案/验收 → 失败测试 → 最小修复 → 回归 → 证据
```

### 新功能 / 多端改造（1–3 天）

```text
基线 + 契约 + 默认清单
→ 纵向切片（数据/API/权限/端/异常）
→ 每片测试与截图
→ 三端联调
→ 证据表 + 未测项
```

### 发布 / 真实集成

```text
预检（测试/构建/备份/手工步骤/回滚）
→ 部署
→ 健康/内容/读回
→ 三端版本表
→ 平台手工步骤
```

## 12. 项目启动卡（每个新项目填一次）

```text
项目：
权威工程/分支：
视觉基线：
角色与范围：
外部能力（支付/登录/打印/平台）：
数据与备份：
部署形态：
授权边界（能改什么/不能改什么）：
完成定义（E 级别）：
本次非目标：
```

> 这张卡填完，后面 80% 的“要不要做/在哪做/算不算完成”都不用再问。

## 13. 完成定义（DoD）

一条功能只有同时满足以下九项，才能说“完成”：

- [ ] 入口可达，主路径能走通
- [ ] 默认项已做或写明 N/A + 原因
- [ ] 权限正反用例通过（含直接 HTTP）
- [ ] 数据落库/重启/重进能读回
- [ ] 空、载、错、断网、重复、超时已处理
- [ ] 关键操作有反馈、防重复、可恢复
- [ ] 视觉与基线对照（两档截图 + computed style）
- [ ] 测试/构建/真机证据带 E 级别
- [ ] 未测项、手工步骤、回滚方式已写清
