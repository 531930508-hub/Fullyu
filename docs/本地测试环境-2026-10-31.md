## 4. 建议测试路径

**顾客端**：选门店（当前门店置顶）→ 茶单（全部/系列切换、¥2/杯会员立减提示、搜索、冷热、售罄）→ 商品规格加购（鲜酿选温度冰量；零售只选数量、无冰量分杯）→ 手机号登录 → 结算（堂食/外带；堂食扫过桌签直接显示固定桌号、可重新扫码，未扫则到吧台取餐口自取；备注、优惠券抵扣）→ 确认门店（显示送达桌号或取餐口自取，可换店并回到确认）→ 支付 → 取茶凭证/提货码 → 订单（全部/鲜酿/零售记录/待领取；列表内查看提货码或取茶凭证是可关闭的子页面，底部仍是订单，关闭后保留筛选与列表）→ 带回家（券与积分资产、我的权益）→ 我的（资料、会员码小图标、券/积分/待领取）。

**营业台**（店长或店员账号）：今日概览 → 代点下单 → 扫码出餐（杯贴逐杯）→ 零售提货码核销 → 报损提交 → 代点草稿刷新恢复（90 分钟）。

**总部后台**（超管/财务账号）：门店管理（**门店配置 → 微信原生扫一扫**：填写桌签链接前缀后，桌签名片改为 https 链接码，顾客用微信「扫一扫」可直接拉起小程序并落到门店与桌号；**取餐位置与桌签**：点击位置预览桌签、单张下载 PNG、打印/导出全部或下载全部桌签 PNG）→ 商品与库存 → **优惠券**（新建通用/指定品类券、有效期、门槛；按手机号发放并查看成功/跳过明细）→ 财务流水/费用录入与导入/门店利润（切换今天/近 7 天/近 30 天/自定义后重新统计，查询中显示「正在按区间统计」）→ 审批 → 退款规则 → 操作记录。

**关键回归点**：

- 支付异常（断网/失败）必须提示“支付未完成”，绝不显示“支付完成”；待支付订单不出餐。
- 未支付订单看不到取茶凭证的“已支付”，支付回调后自动恢复。
- 售罄商品不可加购；空购物袋拦截下单；重复提交有保护。
- 退款超过门槛走审批，未审批不落账；门店只能操作本店数据。
- 筛选条件、统计区间、结算备注、购物袋刷新后保留；购物袋按门店隔离。
- 总部报表切换今天/近 7 天/近 30 天/自定义后重新请求；每日营业额按所选天数补零（无流水日期显示灰色短柱），查询中显示「正在按区间统计」；鼠标悬停或用键盘聚焦柱子会显示该日销售额、净收与流水笔数（提示框在首尾柱会自动内收，不会溢出面板）。
- 桌签扫码（小程序内扫码、启动参数 `scene=sh|窗边01`，或微信原生扫码回传的 `q=https://.../qr?store=sh&seat=窗边01`）可落门店与桌号。
- 门店配置中可预览、下载单张桌签 PNG，或下载/打印全部桌签用于实体制作。

**微信公众平台配置清单（原生扫一扫）**

1. 前置：小程序代码已用 AppID `wxd9e4e4568d1bc8bb` 发布（开发版/体验版只能做测试，正式对外必须先发布代码）；准备一个已通过 ICP 备案的域名，建议使用 https。微信规则本身支持 http/https，但时叙后台只接受 https，避免桌签长期张贴时链接被篡改。
2. 校验收属：在小程序后台下载微信校验文件，按页面提示放到域名根目录或规则 URL 的最后一级目录，确保能通过 https 直接访问该 `.txt` 文件。链接前缀本身不需要真的放一个网页。
3. 新增规则：微信公众平台 → 开发管理 → 开发设置 →「扫普通链接二维码打开小程序」→ 开启 → 新增：
   - 二维码规则：与后台「链接前缀」完全一致；前缀必须带路径（如 `/qr`），末尾不加 `/`，不要带 `?store=...` 参数；
   - 功能页面：`pages/index/index`。
4. 测试：测试范围可选开发版/体验版/线上版；每条规则最多 5 条测试链接，需填完整链接（含 `?store=...&seat=...`），只有管理员/开发者/体验者扫码才生效。测试链接可从后台桌签弹窗复制。
5. 发布：先发布小程序代码，再发布二维码规则；规则未发布时扫码不会进入小程序。发布后，所有符合前缀的链接（所有门店与桌位）自动生效。
6. 限制：一个账号最多 500 条前缀规则，每月最多发布 500 次；本场景 1 条规则即可覆盖全部门店桌位。
7. 参数：微信会把原链接放进 `q`，并附带 `scancode_time`；小程序需对 `q` 做一次 `decodeURIComponent`。时叙解析器已兼容 `q`、`scene`、直接参数和纯文本，并做最多两层解码。
8. 常见不跳转原因：协议不一致、域名不一致、参数不满足前缀匹配、规则未以 `/` 结尾却扫子路径、命中未发布规则。时叙的链接是在前缀后追加查询参数，因此规则不要带参数、不要加尾斜杠。

## 5. 已知边界（测试时不必当缺陷）

- 8 项对外能力全部 mock：支付不真实扣款，打印、泡茶机、平台、会员、微信、对象存储、资料同步均为适配层。
- 优惠券为本次新增：服务端核验归属、状态、有效期、品类与门槛，mock 支付成功后核销；停用后未使用的券立即失效。暂不支持修改已创建券的面额/门槛（可停用后新建）。
- 积分当前只展示会员余额（种子顾客为 0），尚无赚取与消耗规则接入。
- 小程序为单页结构（7 个界面 + 8 个弹层），无原生 tabBar 与页面栈；桌签可通过启动参数 `q`/`scene` 落到单页并自动绑定门店与桌号，但其他分享链接与返回键落地仍受限。
- 桌签二维码有两种形态：未配置链接前缀时为纯文本码（内容 `门店ID|位置名`），微信“扫一扫”只会显示文本，需在小程序内点「扫桌签」；配置链接前缀后为 https 链接码（`前缀?store=门店ID&seat=位置名`）。链接码要真正被微信原生「扫一扫」直接拉起，还需：已 ICP 备案的域名与可访问的微信校验文件、微信公众平台「开发管理 → 开发设置 → 扫普通链接二维码打开小程序」配置并发布规则、小程序代码先发布（测试链接只对开发版/体验版/线上版中的指定用户生效）。这些属于外部配置，本地无法端到端验证，测试时请以小程序内扫码与 `q`/`scene` 启动参数验证落地逻辑；完整步骤见上一节配置清单。位置改名或删除后旧桌签失效，需要重新下载打印（两种形态都如此）。
- 本地测试数据的订单与流水集中在当天，选择多日区间时只有当天有柱高，其余日期是补零空柱；这不是区间未生效。
- 未部署到任何服务器；CORS、登录页账号卡片、限流等属上线前事项。
- 微信开发者工具：`apps/miniprogram/dist/build/mp-weixin` 为最新构建（含本轮整改），使用需自备 AppID 权限；支付仍为 mock，缺支付参数时会如实失败。
