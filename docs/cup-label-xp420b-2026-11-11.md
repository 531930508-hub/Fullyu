# 杯贴打印：芯烨 XP-420B（2026-11-11）

> 门店实际采购的是 **芯烨 XP-420B**（USB / TSPL / 203dpi），不是飞鹅那类自带 4G 的云打印整机。
> 飞鹅适配保留为备选（`PRINTER_DRIVER=feie`），生产默认走 `agent`。

## 1. 链路（为什么方向是反的）

```
小程序下单 → 订单事务内写 print_jobs(queued) → 云端按 40×60 版式渲染 TSPL
                                                    ↓
                          门店电脑上的打印代理每 1.5s POST /api/print-agent/claim
                                                    ↓
                       USB RAW（UTF-8 → GB18030）→ XP-420B 出纸 → 回执 /result
                                                    ↓
                                   job=printed，order.print_status=printed
```

USB 口在门店里，云端够不到，所以只能让门店来取任务。这样做的代价是多一个要维护的
Windows 代理，收益是**绝不假成功**：没出纸就一直 `queued`，超时/失败有退避、死信与补打留痕。

## 2. 版式（320 × 480 dots，1 mm = 8 dots）

| 元素 | 点阵 / 字号 | 位置 | 说明 |
| --- | --- | --- | --- |
| 品牌 Full愈·时叙 | 24×24 (3mm) | `20,20` | 中英之间不留空格、字距收到 2 点，整行右缘 166，不跟右上角杯序抢 |
| 杯序 1 / 2 | 12×20 (2.5mm) | 右对齐 `y24` | 核对整单齐不齐的唯一凭据 |
| 细线 ① | 280×2 | `y54` | TSPL `BAR`，2 dots 是最稳的细线 |
| 眉题 取餐号 | 24 (3mm) | `20,64` | 只留中文，2mm 英文会把取餐号挤得没呼吸 |
| 取餐号 | 32×48 (6mm) | `20,94` | 唯一主角；字距 4 点，比正文更宽 |
| 称呼 | 24 (3mm) | 右对齐 `y113` | 与取餐号下半部对齐；预算 **3 个字格**（1 汉字 = 1 格、1 字母 = 半格），超了补「…」；永不含手机号 |
| 细线 ② | 280×2 | `y176` | |
| 系列 | 3mm + 2mm | `20,186` / `+12,+4` | `醒` + `GOOD DAY`，英文右移 12 点、基线抬 4 点，不抢中文 |
| 品名 | 24 双打 | `20,216` | TSPL 无字重，同行错 1 点打两遍即加粗 |
| 温度 · 冰量 / 时间 | 3mm / 2.5mm | `y254` | 左栏温度、右栏时间；时间右对齐，门店时区 |
| 细线 ③ | 280×2 | `y284` | |
| 二维码 | 21×21 模块 ×5 | `108,294` | 13.1mm，码值 = 杯贴码（`A001-1`），不是取餐号 |
| 门店 | 3mm | 居中 `y408` | 只印店名（`Store.short`），不带城市前缀；280 点可容约 10 个汉字 |
| 电话 | 2.5mm | 居中 `y438` | 未配置 `TEAHOUR_SERVICE_PHONE` 时整行不印 |

单号不上杯贴：顾客和吧台都不读它，省下的一行换成行距。

点阵字体没有字距参数，渲染器逐字发 `TEXT`、自己往右挪，字距集中在 `CUP_LABEL_TRACK`：
品牌 +2 点（收紧，别让门面像被拉散的标题）、正文中文 +3 点（0.375mm）、ASCII +2 点，
取餐号 +4 点，时间 +1 点（小字拉太开反而碎）。空格不发指令但照样占位。
省略号按全角算——中文点阵的「…」占满一格，宁可多留 12 点，也不让右对齐的那行戳出 300。

版式常量只有一份：`packages/integrations/src/label/tspl.ts` 的 `CUP_LABEL_LAYOUT`（坐标）
与 `CUP_LABEL_TRACK`（字距）。服务端渲染、代理转码、设计稿三处都以它为准，改版式只改这里 + 跑测试。

## 3. 数据字段

`PrintJobPayload` 每个 label 新增（都可缺省，旧任务照样能打）：

| 字段 | 来源 | 缺省行为 |
| --- | --- | --- |
| `pickupCode` | `Order.pickupCode` | 从杯贴码反推前缀（`A001-1` → `A001`） |
| `series` | `OrderItem.series` | 不印英文系列名 |
| `customerName` | `Customer.name`（取昵称） | 印「茶客」；超过 3 个字格截断（中文 3 字 / 英文 6 字母 +「…」） |
| `storeName` | `Store.short` | 取不到 short 才退 `Store.name`，再退 `storeId`；城市不上杯贴 |
| `storePhone` | `TEAHOUR_SERVICE_PHONE` | 不印该行 |
| `orderedAt` | `Order.paidAt ?? createdAt` | 退回 `printedAt` |

## 4. 接口与鉴权

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/print-agent/health` | 自检：令牌→门店、传输方式 |
| POST | `/api/print-agent/claim` | 原子领取本店最早一张，返回渲染好的 TSPL |
| POST | `/api/print-agent/jobs/:id/result` | `{ok:true}` 才算打印完成；`{ok:false,error}` 转退避重试 |

- 令牌即身份：`PRINT_AGENT_TOKENS='{"sh":"<48 hex>"}'`，服务端哈希后定长时间比较；
- 令牌为空时接口一律 401（杯贴里有顾客称呼，不能匿名下发）；
- 跨店领取/回执一律拒绝；同一门店多工位并发领取不会重复出纸（`updateMany` 条件认领）；
- 代理崩溃留下的 `processing` 任务在租约（5 分钟）过期后被同店重新领走。

## 5. 部署清单

1. 服务端 `.env`：`INTEGRATIONS_PRINTER_MODE=live`、`PRINTER_DRIVER=agent`、`PRINT_AGENT_TOKENS`、TSPL 纸宽/纸高/间距；
2. 营业台：装 XP-420B 驱动 → 拷贝 `deploy/print-agent/` → 填 `agent.config.json`；
3. `xprinter-agent.ps1 -Test` 打自检标签，确认中文、二维码、边距；
4. `install-task.ps1` 注册登录自启；
5. 下真单验收：出纸即时、后台状态变「已打印」、断代理后订单停在「待打印」。

## 6. 测试

- `apps/server/src/hardware/tspl-label.spec.ts`：版式坐标、字距占位、取餐号 6mm、二维码码值、字宽截断、转义、时区；
- `apps/server/src/printing/print-agent.spec.ts`：不假成功、令牌/跨店隔离、回执、退避死信、租约恢复；
- 全量 `pnpm --filter @teahour/server test` 覆盖既有飞鹅链路（备选方案不回归）。

## 7. 已知风险（真机才能定论）

| 风险 | 处理 |
| --- | --- |
| 机身缺 `TSS24.BF2` 中文点阵 → 方块 | 服务端 `TSPL_FONT_CN` 换 `TST24.BF2` 重发；仍方块则固件是 ZPL 模式 |
| 编码不对 → 乱码 | 代理默认 GB18030；个别固件吃 UTF-8，改 `encoding: "utf8"` |
| 纸卷间距与 `GAP` 不符 → 走纸偏移 | 按纸卷调 `TSPL_LABEL_GAP_MM`，自检标签复验 |
| 13.1mm 二维码在脏杯/水汽下扫不出 | 已有 `docs/scan-samples-2026-11-05` 尺寸结论，13mm 为下限，不再缩小 |
| 浓度偏低导致细线断 | `TSPL_DENSITY` 8 → 9/10 |
