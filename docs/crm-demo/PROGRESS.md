# Full愈 CRM 总部后台 demo · 分阶段进度

依据：`docs/superpowers/specs/2026-11-07-fullyu-crm-design.md`（用户已认可）。
性质：本地交互 demo，全部合成数据，不连接任何真实系统；不是部署、写库、提交或发布授权。
打开方式：双击 **`crm-admin.html`**（单文件合并版，可单独发给他人，file:// 即可，无需服务）；开发时改源文件并打开 `index.html`，改完运行 `python3 build-single.py` 重新生成单文件。

## 文件职责（每阶段只新增 page-*.js，并在 index.html 加一行 script）

| 文件 | 职责 |
|---|---|
| `crm-admin.html` | 单文件交付版（生成物，约 249 KB，无外部依赖）；不要手改，改源文件后重新生成 |
| `build-single.py` | 把 `crm.css` 与 `index.html` 中的 10 个脚本按原顺序内联成 `crm-admin.html` |
| `index.html` | 外壳挂载点与脚本顺序（开发入口） |
| `crm.css` | V7 token（来自 `apps/admin/src/v7.css`）+ CRM 组件；字距 0.05/0.06/0.12/0.18em |
| `data.js` | 合成数据：8 位会员、角色权限（阶段 4 新增 `role:edit`，仅管理员）、权益快照、汇总、审计 |
| `page-config.js` | 阶段 4：规则配置（积分规则按时叙/轻疗/在场、骰子规则全业务；现行 vs 待生效对比、积分试算、新建版本校验、生效前撤销）、月度对账（10 月定稿 / 11 月至今预估；售卡按售卖业务、已享优惠与积分消耗两张矩阵、余额勾稽、与工作台积分负债核对、CSV 导出）、角色权限（管理员编辑草稿 → 依赖校验 → 填原因保存即生效，职责分离提示） |
| `shell.js` | 路由 `#/页面/参数`、侧栏分组、角色切换、对话框、toast；`CRM.pages` 注册页面，未注册路由显示「页面不存在」并可回工作台 |
| `data-profile.js` | 2026-11-08：会员资料（称呼/城市/来源/标签/备注）、各业务最近登录与消费统计（含 12 个月到访）、业务会员卡、大会员卡产品与版本、业务卡目录、积分调整单 |
| `page-members.js` | 工作台（含会员关怀人群）、会员查询（9 列 + 人群筛选）、会员 360（7 个页签：概览/资料与轨迹/消费分析/权益卡/积分/愈行之旅/身份与授权）；`CRM.calc` 提供余额/退卡测算 |
| `page-points.js` | 积分调整：单笔（≤500 直接入账，>500 待审批）、批量（逐行校验 → 一律待审批）、审批/驳回（审批人≠发起人、审批时重新校验、整单不执行） |
| `page-benefits.js` | 权益：大会员卡（基础信息、三端权益、版本只追加、待生效版本可撤销）+ 业务会员卡目录（只读） |
| `page-sync.js` | 阶段 3：三端同步——接收端卡片（回调地址、HMAC key_id 引用、出口 IP、最近送达、下次重试）、快照落后会员表、outbox 事件表（按业务/状态筛选、单条或整批按版本从旧到新重投、退避 1/5/30 分钟 · 2/6/12/24 小时）；`CRM.emit(type, 会员)` 供其他页面写操作后投递，接收端故障时快照标记落后 |
| `page-queue.js` | 阶段 3：异常队列三个页签——人工队列（开卡金额不符：退款或补差开卡；积分预占超时：补扣或向顾客收回；出站事件超 24 小时：幂等补发或作废）、对账差异（以业务端 / 以 CRM 为准 / 说明不调整）、身份冲突（拆分保留两人或审批合并，双方都有有效卡时禁止合并，合并迁移批次/身份/卡期并作废被合并方待审换绑）；每项处理须填说明并写审计 |
| `page-approvals.js` | 阶段 2：审批中心（退卡 / 换绑 / 积分调整 / 明文导出四类，按待审批·进行中·已完结筛选）、退卡全生命周期（审批→锁卡→渠道结果未知→确认或中止，业务端回调用「演示」框模拟）、换绑手机号、会员导出（默认脱敏 CSV，明文需审批且仅发起人下载一次）、审计日志页（按动作/操作人/关键词筛选） |

扩展约定：`CRM.pages[key] = { title, render(params) }`；按钮 `data-act="x"` → `CRM.act.x(el)`；输入 `data-input="x"` → `CRM.input.x(el)`；写操作调用 `CRM.audit(动作, 对象, 详情)`；权限用 `CRM.can('perm')`。
