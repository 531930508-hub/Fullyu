# 时叙系统审计与可复用 AI 开发指导包

2026-10-30。本包是审计和方法论交付，**不是漏洞已经修复、不是上线批准**。

## 先看结论

时叙不是“只有页面、所有数据都在内存”，已有真正的三端与业务数据库底座。但身份、门店范围、收退款、部分履约、配置消费和失败恢复仍有缺陷；采购、对账与真实渠道等闭环尚不足，不能认定为可可靠营业的连锁系统。

报告与台账共整理 **36 项风险/能力缺口：11 项 P0、23 项 P1、2 项 P2**。P0 指真实营业前的阻断项，包含尚未落地的真实能力，不代表已发生11起安全事故。

本次隔离验证取得了 **10 项问题/配置风险的动态证据**，包括会员码冒用、空门店范围扩权、成本字段暴露、密码重置后旧令牌可用、生产默认配置问题，以及冷热合并、重复打印任务、迟到付款库存错位和部分退杯仍可出餐。并发竞态未全部动态复现，已单独标明。

现有后端 **102 项测试仍通过**，其中甚至有测试把会员码冒用路径当正确行为。因此今后不能再用测试数量、页面截图或构建通过来概括系统完成度。

## 建议的处理顺序

1. 身份/门店范围与生产安全配置先处理。
2. 以一笔订单贯穿支付、出餐/领取、退款、库存、流水，修正交易不变量和失败恢复。
3. 补后台配置的消费端、版本/刷新、分页与错误态，保留现有视觉。
4. 补采购/库存凭证、跨店履约、对账关账；只对真正影响经营口径的问题做决策。
5. 得到授权后，才接真实渠道、真机、设备和试点门店，做完整营业与恢复验收。

## 本次改动与限制

- 新增本指导包、隔离审计探针、整改台账、项目 AGENTS 入口。没有修改业务源码、schema、实际权限、生产数据或在场工程。
- 本次构建 shared/integrations/server、运行后端测试及临时库探针；没有重跑 admin/小程序浏览器或微信真机，没有访问真实支付/打印/会员/外卖/在场接口。
- 构建会生成本地 dist，不是业务实现变更。没有 Git 提交/push/发布，没有覆盖之前的开发交付 ZIP。
- 台账当前均为未整改；其中能力缺口须在相应功能范围确认后实施，不能把所有条目未经评估一口气写进生产。
- 文件内源码链接指向本机绝对路径，分享给其他开发环境需映射工程位置。包内文档互链为相对路径；外部源码不随本包复制，内部材料不得自动外发。

## 如何复核证据

[local-probes.cjs](evidence/local-probes.cjs)仅用于当前缺陷取证，读取构建后的服务模块，创建临时 SQLite 并只监听 127.0.0.1。调用渠道固定 mock；结果不包含令牌、密码或真实顾客数据。

从当前项目根运行，先按批准的验证流程构建依赖和 server，然后运行：

```bash
node docs/system-audit-2026-10-30/evidence/local-probes.cjs
```

探针退出 0 只说明脚本执行完，不能作为“系统安全通过”。未来修复后必须把安全目标转成独立断言测试，不可以要求旧漏洞继续出现。

[server-tests.txt](evidence/server-tests.txt)是本次后端测试输出。[SHA256SUMS](evidence/SHA256SUMS.txt)用于核对本包文件；[source-fingerprints.json](evidence/source-fingerprints.json)只记录被文档引用源码的路径、行数和哈希，不复制源码或凭证。指纹证明对应快照，不证明源码质量；源码变更后需要重新核验结论。
