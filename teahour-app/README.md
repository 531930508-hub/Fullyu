# Full愈·时叙 — 茶饮门店运营系统

按已评审 V7 方案落地的可运行全栈版本：顾客点单、营业台出餐、总部财务与运营费用管理、门店利润核算、权限审批，以及支付/打印/泡茶机/平台/会员的预留适配接口。

> 这是 **可运行的演示系统**，不是上线批准。支付、打印、泡茶机、外卖平台、会员均为 mock；数据为演示数据；未做生产部署与真实商户配置。

## 快速开始

环境：Node.js ≥ 20.11（开发验证于 20.18.1）

```bash
npm install
npm run dev        # API http://localhost:8787 + Web http://localhost:5173
```

首次启动会自动建库 `data/teahour.db` 并写入门店、商品、角色与演示交易。也可以手动初始化：

```bash
npm run seed
```

生产式运行（同一端口同时提供 API 与静态前端）：

```bash
npm run build      # 构建 web/dist 与 server/dist
npm start          # 默认 http://localhost:8787
```

`npm start` 使用 Node 的 `--env-file` 版本：`npm run start:env`（读取根目录 `.env`）。

## 技术结构

```
teahour-app/
├── server/src/
│   ├── routes/        auth / customer / store / admin
│   ├── services/      订单、打印、报损、财务、费用、利润、权限
│   ├── db/            schema 与种子（SQLite，WAL）
│   ├── hardware/      打印、泡茶机、支付、平台、会员适配层 + README
│   └── app.ts         Fastify 装配、静态站点、统一错误处理
├── web/src/           React 18 + Vite，顾客端 / 营业台 / 总部后台
├── server/test/       node:test 集成测试
└── tests/             Playwright 浏览器验收脚本
```

- 后端：Fastify 5、better-sqlite3、zod、@fastify/jwt、bcryptjs
- 前端：React 18、React Router 6、Vite 5、TypeScript strict
- 金额全部为整数分；SQLite 开启外键与 WAL；JWT 员工 12 小时、顾客 30 天

## 环境变量

复制 `.env.example` 为 `.env` 后按需修改；开发时也可直接 `export`。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | API / 静态站点端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATABASE_FILE` | `data/teahour.db` | SQLite 文件路径，`:memory:` 可用于测试 |
| `JWT_SECRET` | 开发占位值 | **生产必须替换**，否则令牌可被伪造 |
| `DEMO_DATA` | `1` | 设为 `0` 时不写入演示交易（基础商品/账号仍会初始化） |
| `DEMO_PASSWORD` | `teahour2026` | 首次建库时的员工初始密码 |
| `API_ORIGIN` | `http://localhost:8787` | Vite 开发代理目标 |

## 硬件与外部系统

所有真实设备/渠道接入点集中在 `server/src/hardware/`，详见 [硬件适配说明](server/src/hardware/README.md)。当前 `mock`：

- 云标签打印：下单后写入 `print_jobs` 并立即尝试打印，失败保留队列供补打
- 支付/退款：mock 网关返回流水号；退款必须先通过审批/权限
- 泡茶机：仅预留状态与冲泡接口，不进入下单主流程
- 美团/淘宝：仅定义拉单与确认接口，未启动轮询
- 会员：`TH-` 码校验，年会员每杯减 ¥1

替换方式：实现 `contracts.ts` 中的接口，在 `hardware/index.ts` 切换实现。真实接入前必须补齐幂等、验签、超时重试、密钥管理与门店设备绑定。

## 已知边界

- SQLite 单机适合演示与小规模试点；多实例/高并发需迁移 PostgreSQL 并调整事务与锁策略
- 无真实支付、打印、外卖、会员与在场系统对接；无短信、推送、对象存储
- 演示数据可重复生成，但删除 `data/teahour.db` 会丢失新增业务数据
- 未包含反向代理、HTTPS、备份、监控、限流等生产运维配置
- CSV 导入按现有字段校验；导入失败会返回逐行错误，不会部分写入

## 安全提示

- 演示密码与 `JWT_SECRET` 不得用于生产；生产需接入统一登录/密钥管理
- 财务与内部数据不得导出到公开链接；日志中避免出现会员码、手机号与支付凭据
- 当前无速率限制与 CSRF 专项防护，公网部署前必须补齐
