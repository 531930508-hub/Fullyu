# 2026-11-20 杯贴压字 / 热饮「标准冰」占位 / 删除飞鹅通道 发布说明

## 1. 问题（真机反馈）

40×60 杯贴上三个叠在一起的问题：

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 规格行「冰 · 标准冰」与下单时间叠字、日期被裁 | 规格行与时间共用 y=254 的 35mm 一行：规格预算 140 点、时间 142 点，合计 292 点 > 版心 280 点，左栏截断右栏压字 |
| 2 | 热饮印成「热 · 标准冰」 | `normalizeTeaOptions` 给热饮回填 `ice: '标准冰'` 占位（V7 遗留），杯贴/小票/后台都直接拼 `temp · ice` |
| 3 | 飞鹅云通道从未接入生产 | 整机是芯烨 XP-420B，只走条码云或 USB 打印代理；飞鹅分支是早先的技术选型残留 |

## 2. 改动

| 层 | 文件 | 变化 |
| --- | --- | --- |
| 数据口径 | `apps/server/src/orders/orders.service.ts` | 热饮 `ice` 落库为 `null`（不再写「标准冰」占位）；旧客户端传「热饮」「标准冰」仍兼容，传其它冰量报 400 |
| 数据口径 | `apps/server/prisma/seed.ts` | 种子单同步 `ice: null` |
| 杯贴·TSPL | `packages/integrations/src/label/tspl.ts` | 规格行独用整行（预算 = 版心 280 点）；下单时间上移到眉题行右端（y=64），与「取餐号」同行且留 60 点呼吸；`optionLine` 对温度=热一律丢弃冰量 |
| 杯贴·条码云 | `packages/integrations/src/providers/live/xpyun.ts` | 同上：时间由 y=32 移到 y=8（眉题行，右对齐 37mm），规格行预算 17.5mm → 34mm |
| 后台 | `apps/admin/src/lib/lineOptions.ts`、`StoreApp.tsx` | 新增 `lineOptionText`：热饮只显示温度，历史单的占位冰量不上界面 |
| 顾客端 H5 | `apps/miniprogram/src/pages/index/index.vue` | 小票/凭证行同样按「热饮不显示冰量」拼（与结算行口径一致） |
| 通道清理 | `packages/integrations/src/{config,contracts,index}.ts`、`providers/live/{index,feie}.ts` | 删除飞鹅驱动与 `FEIE_*` 配置；`PRINTER_DRIVER` 只接受 `xpyun`（默认）/ `agent` |
| 配置样例 | `apps/server/.env.example` | 去掉 `FEIE_*`，`PRINTER_DRIVER` 默认改 `xpyun` |

**历史数据不回填**：已出的单子里 `ice='标准冰'` + `temp='热'` 的行保留原样，渲染与展示层按温度兜底，
所以纸质杯贴、后台订单详情、顾客小票都不会再出现「热 · 标准冰」。

## 4. 发布步骤

无 DDL、无 prisma schema 变更，不需要 regenerate client。

1. **备份**
   ```bash
   BK=/opt/teahour/backups/release-$(date +%Y%m%d-%H%M%S); mkdir -p $BK
   tar czf $BK/app-dist.tgz -C /opt/teahour/app apps/server/dist apps/admin/dist \
     apps/miniprogram/dist/build/h5 packages/integrations/dist packages/shared/dist
   tar czf $BK/nginx.tgz -C /etc/nginx sites-enabled sites-available
   ```
2. **同步产物**：`apps/server/dist`、`packages/integrations/dist`、`packages/shared/dist`、
   `apps/admin/dist`、`apps/miniprogram/dist/build/h5` → `/opt/teahour/app/...`，`chown -R root:teahour`。
   H5 必须用 `VITE_BASE=/mp/` 的产物，否则 `index.html` 引到 `/assets/`（后台的目录）会 404。
3. `systemctl restart teahour-api`，日志无 ERROR。
4. **测试环境额外一步（生产不需要）**：测试机 `test-teahour.fullyu.cn` 原来只反代了后台，
   `/mp/`（顾客端 H5）落到后台的 `try_files` 会打开一个空后台页。本次在
   `/etc/nginx/sites-enabled/test-teahour.fullyu.cn.conf` 里补了与生产同构的
   `/mp/assets/`、`/mp/static/`、`/mp/index.html`、`/mp/`、`/static/` 五个 location，
   `nginx -t` 通过后 reload。生产 nginx 无需改动（`teahour-teahour.fullyu.cn.conf` 已有这些块，
   本次只核对 alias 路径仍指向 `apps/miniprogram/dist/build/h5/`）。
