## 9. 发布当天事故：后台优惠券「服务暂时不可用」

| 项 | 内容 |
|---|---|
| 现象 | admin 优惠券页报「服务暂时不可用，请稍后重试」；日志 `TypeError: Cannot read properties of undefined (reading 'groupBy')`，接口 500 |
| 根因 | 首轮部署只 rsync 了 `dist`，生产 `node_modules/@prisma/client` 仍是 11-13 生成的旧模型（只有 `coupon`、`customerCoupon`），没有 `couponBatch`、`couponRule`；`coupons.service` 调 `prisma.couponBatch.groupBy` 时对象为 undefined |
| 次生问题 | 补生成时把仓库 SQLite 版 `schema.prisma` 直接 scp 上生产，生成出 `provider = "sqlite"` 的 client，服务启动即崩（`URL must start with file:`），API 整体不可用约 1 分钟 |
| 修复 | 用 `sed` 把 provider 改为 `mysql` 生成 `schema.mysql.prisma` 后再 `prisma generate`，重启；health 200 |
| 验证 | 短时签发 staff token 调读接口：`/api/admin/coupons` 200 空列表、`/coupons/records` 200、`/coupons/rules` 200、`/coupons/batches` 200；token 已即时销毁 |
| 规则 | 生产 Prisma client 必须用 **mysql provider 的 schema** 生成；改 schema 的发布，`prisma generate` 与 `dist` 同步缺一不可（playbook 3.1 的 schema 项此前只写了 generate，未写 provider） |
## 10. 发布当天修复：新建自动发券规则 400 + 会员层级文案

| 项 | 内容 |
|---|---|
| 现象 | 「新建模板」弹窗提交报「请求参数不完整或格式不正确」 |
| 定位 | Nginx 日志显示券模板 POST 为 201，真正 400 的是 `POST /api/admin/coupons/rules`：admin 表单用 `kind=newcomer`、`config.windowDays`，服务端契约是 `kind=welcome`、`config.withinDays`，Zod 枚举直接拒绝 |
| 修复 | admin 的 `CouponRuleKind`/表单/文案对齐服务端（`welcome` + `withinDays`）；服务端给 kind、tier、config 补中文校验提示并拒绝未知字段，避免同类问题再落到泛化文案 |
| 层级文案 | 品牌只有两级：普通会员与 Full愈大会员。规则表单原写「银卡及以上 / 金卡会员」，改为「普通会员 / Full愈大会员」（`standard` = 未持大会员卡，`annual` = Full愈大会员） |
| 验证 | 重新提交 `kind=welcome, tier=standard, config.withinDays=7` → 201 并可在列表读取；用旧 `newcomer/windowDays` 请求返回 400「规则类型不支持，可选生日关怀 / 新客欢迎 / 沉睡唤回」；测试规则已删除 |
