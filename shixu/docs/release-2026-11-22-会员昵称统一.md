# 会员默认昵称统一「会员+手机号后四位」（2026-11-22）

## 背景

同一位会员在三个端看到三个名字：

| 端 | 默认昵称来源 | 形状 |
| --- | --- | --- |
| 时叙 / 在场（用户+号） | 登录没昵称时本地生成 | `用户7229` |
| 轻疗（用户+号） | `NicknameGenerator` | `用户7229` |
| CRM 主档 | 新建会员默认值 | `会员` |
| 老数据 | 一版「随机词+4位」迁移残留 | `茶客` / `青竹4821` |

CRM 是资料主档，时叙小程序「个人资料」页展示的就是 CRM `members.name`，
于是顾客在自己的资料页看到的是别的端起的名字（`用户7229`），看不出是自己的会员号。

业务 2026-11-22 定稿：**默认昵称一律「会员+手机号后四位」**（如 `会员7229`）；
「会员」二字先把身份说清楚，后四位方便店员/客服对号。客户自己改过的昵称不动。

## 改动

### 口径（三端同一套规则）

占位名（没名字时的系统默认值）：`''`、`会员`、`茶客`、`会员XXXX`、`用户XXXX`、`用户+86…`。
信息量排序：真名 3 > `会员+后四位` 2 > `用户+号` 1 > 其它占位名 0。
**只升不降**：真实昵称永远压过占位名；占位名之间不会被更低档的覆盖。

### CRM（资料主档）

- `apps/server/src/common/member-name.ts`：`isPlaceholderName` / `nameRank` / `defaultMemberName`
- `external.service.ts`：resolve 新建/更新时调用 `resolvePlaceholderName`——别的端推上来
  `用户7229` 时落库成 `会员7229`；真实昵称照常升级；`会员XXXX` 不会被 `用户XXXX` 降级。
- `brand-member.service.ts`：`PATCH /v1/brand-member/profile` 推上来的默认昵称同样归一，
  避免轻疗把 `用户7229` 写进主档。

### 轻疗

- `NicknameGenerator` 默认名改为 `会员+后四位`。
- `BrandMemberProfileSync`：CRM 下发的 `members.name` 落 `c_customer.nickname` 前先归一，
  同时保留「本地是真实昵称、远端还是占位名」时不被降级。

### 时叙

- `common/member-name.ts`：与 CRM 同口径的 `isPlaceholderName` / `nameRank` / `defaultMemberName`。
- `auth.service.ts`：没昵称登录不再落「茶客」，默认 `会员+后四位`；CRM 回拉的昵称
  只在信息量更高时覆盖本地（`adoptCrmName`），避免把顾客自取的名字盖回占位名。
