# 发布记录：0 元单（券全额抵扣）建单即落账（2026-11-14）

> 生产影响面（发布前实查）：`orders` 里 0 元单共 2 笔（A001/A002，11-14 06:08，顾客 C-0df1…），均为 `cancelled / failed`，
> 各有 1 条 `processing` 的支付意图滞留；该顾客的 20 元券已回到 `available`，修复上线后可直接重试。
>
> 问题：20 元无门槛券 + 20 元饮品 = 应付 0 元，点「支付」失败。
> 根因：建单后无论金额多少都把 0 元单交给支付渠道（汇付 nativePay/jspay 拒绝「支付金额不正确」），
> 小程序随后把未支付单取消，顾客看到的是「支付失败 + 订单已取消」。
> 修复口径：0 元没有可扣金额，任何渠道都会拒绝——建单即按已支付落账，绝不向渠道下发 0 元支付。

## 2. 服务端行为（发布后）

1. `POST /api/customer/orders`（现做/零售，非外卖平台）：
   `prepared.totalCents <= 0` → `settleZeroOrder`：`markPaid(订单, 'ZERO-<orderId>')` → 支付意图落 `succeeded`（`payment: {kind:'none',status:'paid'}`）→ `finishOrder`（取餐号/杯贴/会员统计照常）。
   券在 `markPaid` 内由 `reserved` 转 `used`；库存照常扣减。
   订单若已被取消（`blocked-cancelled`），返回 409「订单已取消，请重新下单」。
2. `POST /api/customer/orders/:id/prepay`：`order.totalCents <= 0` 时补记落账并返回
   `{ paid: true, prepayMode: 'none' }`，覆盖发布前已产生的 0 元未支付单（历史单兜底），客户端不再拉起微信收银台。
3. 非 0 元单路径逐字未动：异步渠道仍走预下单/收款码/付款码 + 回调落账，同步 mock 渠道行为不变。
